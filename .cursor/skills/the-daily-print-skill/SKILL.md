# The Daily Print — 个人日报生成器

## 描述

The Daily Print 为任何用户生成个性化的每日 HTML 报纸。根据用户兴趣自动发现 RSS 订阅源，让用户挑选或自行输入，然后每天从已订阅的源中抓取热点内容，翻译整理后生成一份报纸风格的 HTML 页面。

行为规则以本 `SKILL.md` 为准；`README.md` 仅用于介绍。

## 触发条件

当用户说出以下类似表达时，使用此 Skill：
- "生成今日日报" / "出一期日报" / "更新日报" / "generate daily newspaper" / "the daily print"
- "我想订阅 RSS" / "管理我的订阅" / "添加订阅源"
- "修改日报名称" / "换个报纸名"

## 持久化数据

本 Skill 在运行目录下维护一个 `user-config/` 文件夹，用于存储用户的个人配置。**每次执行时先检查这些文件是否存在。**

```
the-daily-print/
├── SKILL.md
├── references/
│   ├── template.html          ← HTML 模板
│   └── style-guide.md         ← 排版规范
└── user-config/                ← 用户配置（运行时创建）
    ├── profile.json            ← 报纸名称、用户偏好
    └── subscriptions.json      ← 已订阅的 RSS 源列表
```

### profile.json 格式

```json
{
  "newspaper_name": "Zach的日报",
  "motto": "每日精选 · 科技前沿 · 赛场风云",
  "interests": ["科技", "NBA", "编程"],
  "output_dir": "X:\\zach-openclaw-workspace\\daily-newspaper",
  "file_prefix": "zach-daily-newspaper",
  "language": "zh-CN",
  "created_at": "2026-03-30",
  "issue_count": 12,
  "layout": {
    "total_articles": "auto",
    "article_length": "default",
    "target_pages": 2
  }
}
```

**`layout` 字段说明：**

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `total_articles` | `number \| "auto"` | `"auto"` | 总文章篇数。`"auto"` 表示由 AI 自动控制，目标为填满 1-2 页 |
| `article_length` | `"short" \| "default" \| "long"` | `"default"` | 文章摘要篇幅。`short`=30-60 字，`default`=60-120 字，`long`=100-200 字 |
| `target_pages` | `number` | `2` | 目标页数（打印/浏览器预览基准），AI 会据此调节内容量 |

### subscriptions.json 格式

```json
{
  "subscriptions": [
    {
      "id": "ithome",
      "name": "IT之家",
      "url": "https://www.ithome.com/rss/",
      "category": "科技",
      "icon": "📰",
      "added_at": "2026-03-30",
      "status": "active"
    }
  ]
}
```

## 工作流程

### 阶段一：初次使用 — 引导设置（仅首次）

当 `user-config/profile.json` **不存在**时，进入引导流程：

#### 步骤 1：询问兴趣偏好

以轻松的语气询问用户：

> 👋 欢迎使用 The Daily Print！
>
> 在开始之前，告诉我你平时关注哪些领域？可以多选，也可以自由输入：
>
> - 📰 实时新闻（国内/国际热点）
> - 💻 科技（数码、AI、互联网）
> - 💰 财经（股市、商业、创投）
> - 🏀 体育（NBA、足球等）
> - 🎮 游戏（主机、PC、手游）
> - 💡 知识（科普、学术、深度阅读）
> - 🔧 编程（开发工具、技术博客）
> - 🌍 外媒（英文原版新闻）
> - 📱 公众号精选
> - ✏️ 其他（请告诉我）

用户可以直接说"科技和 NBA"、选编号、或自由描述。将用户的选择记录到 `interests` 字段。

#### 步骤 2：推荐 RSS 源

根据用户选择的兴趣领域：

1. 访问 `https://plink.anyfeeder.com/` 获取可用的 RSS 源列表
2. 按用户兴趣筛选出 **每个领域 3-5 个推荐源**
3. 以表格形式展示给用户：

> 根据你的兴趣，我找到了这些订阅源：
>
> **科技类：**
> | # | 名称 | 来源 | 说明 |
> |---|------|------|------|
> | 1 | IT之家 | ithome.com | 国内科技资讯综合 |
> | 2 | 36氪 | 36kr.com | 创业、科技、商业 |
> | 3 | 少数派 | sspai.com | 效率工具、数码测评 |
>
> 输入编号订阅（如 `1,2,3`），或输入自定义 RSS 链接。
> 输入 `全选` 订阅该分类下所有源。

4. 用户也可以直接输入自定义 RSS 链接，AI 需验证该链接是否为有效 RSS/Atom feed。

#### 步骤 3：确认报纸名称

> 给你的日报起个名字吧！比如「XX 的日报」「The Daily Print」「晨间快讯」「每日简报」…
>
> 直接输入名称，或回复"默认"使用「The Daily Print」。

#### 步骤 4：确认内容量偏好

> 你希望日报的篇幅大概多少？
>
> - 📄 **简洁版**（约 1 页，10 篇左右，摘要简短）
> - 📰 **标准版**（约 1-2 页，15-20 篇，默认推荐）
> - 📖 **丰富版**（约 2-3 页，20-30 篇，摘要详细）
> - ✏️ **自定义**（告诉我具体篇数和篇幅）
>
> 回复"默认"使用标准版。

根据用户选择设置 `layout` 字段：

| 选项 | total_articles | article_length | target_pages |
|------|---------------|----------------|-------------|
| 简洁版 | 10 | "short" | 1 |
| 标准版 | "auto" | "default" | 2 |
| 丰富版 | 30 | "long" | 3 |
| 自定义 | 用户指定 | 用户指定 | 用户指定 |

#### 步骤 5：确认输出目录

> 日报 HTML 文件保存到哪个目录？
>
> 回复"默认"使用当前工作区目录，或输入自定义路径。

#### 步骤 6：保存配置

将所有信息写入 `user-config/profile.json` 和 `user-config/subscriptions.json`。

> ✅ 设置完成！已订阅 {N} 个源。随时说"生成今日日报"开始。
>
> 以后你还可以：
> - 说"添加订阅"增加新源
> - 说"管理订阅"查看/删除已有源
> - 说"修改日报名称"更改报纸标题
> - 说"调整篇幅"更改内容量偏好

### 阶段二：订阅管理（随时可用）

#### 添加订阅

触发词："添加订阅"、"新增 RSS"、"我想关注 XXX"

1. 如果用户给了具体链接 → 验证后直接添加
2. 如果用户给了领域关键词（如"足球"）→ 去 `plink.anyfeeder.com` 搜索推荐 → 让用户选择
3. 添加前**检查是否已订阅**（按 URL 去重），如果已存在则提示

#### 删除订阅

触发词："取消订阅"、"删除 RSS"、"不想看 XXX 了"

1. 列出当前所有订阅（带编号）
2. 用户选择要删除的编号
3. 将对应条目的 `status` 改为 `"inactive"`（软删除，保留记录）

#### 查看订阅

触发词："我的订阅"、"当前订阅列表"

以表格展示所有 `status: "active"` 的订阅，按分类分组。

### 阶段三：生成日报

当用户说"生成今日日报"等触发词时：

#### 第一步：检查配置

1. 读取 `user-config/profile.json` — 如果不存在，进入**阶段一**引导设置
2. 读取 `user-config/subscriptions.json` — 如果没有活跃订阅，提示用户先添加
3. 确认报纸名称。如果 `newspaper_name` 字段为空，询问用户

#### 第二步：确定日期与期号

1. 获取**今天的日期**
2. 读取输出目录，找到**最新一期**的 HTML 文件
3. 从最新一期中提取 `第 N 期`，本期 = N + 1
4. 同时更新 `profile.json` 中的 `issue_count`
5. 如果今天已有日报，提醒用户并询问是否覆盖

#### 第三步：抓取 RSS 内容

遍历 `subscriptions.json` 中所有 `status: "active"` 的源：

1. 逐个抓取 RSS feed（最近 24 小时的内容）
2. 如果某个源无法访问，记录失败原因，**跳过但不中断**
3. 如果超过半数的源全部失败，通知用户建议稍后重试
4. **注意：** 如果某个已订阅的源连续多次抓取失败，在结果通知中提醒用户考虑将其删除或替换

#### 第四步：智能分板块

根据已订阅源的 `category` 自动决定板块划分：

**分板块规则：**
- 同一 `category` 的源归入同一板块
- 每个板块选一个合适的 emoji 图标和中文标题
- 板块排列顺序：内容量多的板块靠前
- 如果只有 1 个板块（比如用户只订阅了科技），也完全 OK，不需要凑数

**内容量控制（根据 `profile.json` 中的 `layout` 配置）：**

读取 `layout.total_articles`、`layout.article_length`、`layout.target_pages`，据此分配各板块文章数：

| 模式 | 总篇数 | 主板块 | 次要板块 | 小板块 |
|------|--------|--------|---------|--------|
| `total_articles` 为 `"auto"` | 根据 `target_pages` 自动调节 | 1 头条 + 按比例分配副条 | 按比例分配 | 按比例分配 |
| `total_articles` 为具体数字 | 严格按指定篇数 | 约占 40% | 约占 40% | 约占 20% |

**默认值（`"auto"` 模式，`target_pages: 2`）：**

| 板块类型 | 结构 |
|---------|------|
| **主板块**（文章最多的分类） | 1 条头条（headline-story）+ 最多 9 条副条（columns-3） |
| **次要板块** | 最多 10 条列表形式（list-section 两栏） |
| **小板块**（≤5 条内容） | 直接用 columns-2 或列表 |

> 如果某个板块的 RSS 源是论坛/社区类（如 V2EX、Hacker News），使用 `list-section`（标签 + 标题列表）样式。
> 如果是新闻/资讯类，使用 `article`（标题 + 摘要 + 来源）样式。

**🎯 版面填满规则（重要）：**

生成 HTML 后，AI 需要**预估版面效果**。如果出现以下情况，需要补充内容以确保版面美观饱满：

1. **页面底部有明显空白**（最后一个板块内容过少） → 给该板块多加 2-3 条内容
2. **columns-3 栅格不满**（如只有 4 条，第二行只占 1 格） → 补到 6 条凑满两行，或减到 3 条只放一行
3. **columns-2 栅格不满** → 同理，保持偶数条目
4. **整体页面偏短（不到 1 页）** → 适当增加摘要篇幅，或从 RSS 源中多选几条热门内容
5. **整体页面偏长（超过 target_pages）** → 适当缩短摘要，或减少小板块条目

原则：**宁可多一点内容让版面饱满，也不要留大面积空白。** 美观 > 严格篇数。

#### 第五步：内容筛选与去重

1. **去重：** 读取前一天的 HTML 文件（如果存在），提取所有链接，本期不包含重复链接
2. **筛选：** 优先选择热度高、话题性强的内容
3. **翻译：** 英文内容翻译为通顺的中文（除非用户在 profile 中设置了 `language: "en"`）
4. **专有名词：** 人名、品牌名等使用中文通用译名

#### 第六步：内容编写

为每篇文章编写：

| 字段 | 要求 |
|------|------|
| **标题** | 简洁有力，15-30 字 |
| **摘要** | 长度根据 `layout.article_length` 设置（见下表） |
| **来源标注** | `来源名 · 分类`，如 `IT之家 · 芯片` |
| **原文链接** | 保留原始 URL，`target="_blank"` |

**摘要长度参考：**

| `article_length` | 普通文章摘要 | 头条摘要 |
|-------------------|-------------|---------|
| `"short"` | 30-60 字（1-2 句） | 60-100 字 |
| `"default"` | 60-120 字（2-3 句） | 100-200 字 |
| `"long"` | 100-200 字（3-5 句） | 150-300 字 |

**每日引言（Pull Quote）：**
- 从当日新闻中提炼一句有启发性或趣味性的中文引言
- 放在第一个板块和第二个板块之间

**日期栏名言（Date Bar Quote）：**
- 选一句英文名人名言，格式：`"引言内容" — 作者名`

#### 第七步：农历日期

日期栏包含农历日期，格式：`农历丙午年二月十二`。如无法计算，通过网络搜索查询。

#### 第八步：生成 HTML

1. 读取 `references/template.html` 模板
2. 根据实际板块数量，**动态组装 HTML 内容**：
   - 报头（masthead）：使用 `profile.json` 中的 `newspaper_name` 和 `motto`
   - 按板块顺序填充内容区域
   - 板块之间插入 `ornament` 分隔符
   - 页脚：列出实际使用的数据来源名称
3. **CSS 样式原样保留**，不要修改模板中的 `<style>` 部分

**动态部分：**

| 位置 | 内容 |
|------|------|
| `<title>` | `{报纸名} - {年}年{月}月{日}日` |
| `.masthead h1` | `{报纸名}` |
| `.masthead-motto` | `{motto}` |
| `.masthead-top` | `EST. 2026 | 第 N 期 | 星期X` |
| `.date-bar` | 日期 + 农历 + 名言 |
| 各板块 | 根据订阅源动态生成 |
| `.footer` | 报纸名 + 日期 + 数据来源列表 |

#### 第九步：保存文件

- 路径：`{output_dir}/{file_prefix}-{YYYYMMDD}.html`
- 编码：UTF-8
- 示例：`X:\...\zach-daily-newspaper-20260401.html`

#### 第十步：质量检查

1. ✅ 所有链接 `href` 不为空
2. ✅ 无残留的英文人名（如果 language 为 zh-CN）
3. ✅ 与前一天链接无重复
4. ✅ HTML 格式完整
5. ✅ 报纸名称与 profile 一致
6. ✅ **版面美观检查**：columns-3 栅格行数完整（3 的倍数）、columns-2 条目为偶数、无大面积空白区域
7. ✅ 总篇数符合 `layout` 设置（`"auto"` 模式下在合理范围内即可）

#### 第十一步：结果通知

- **成功：** 告知用户"第 N 期《{报纸名}》已生成"，给出路径；若当前环境支持 `preview_url` 再提供预览
- **部分失败：** 说明哪些源不可用，其余内容照常生成
- **全部失败：** 通知用户所有 RSS 源不可达，建议稍后重试

## 特殊情况处理

### 首次运行无配置
自动进入阶段一的引导设置流程，不要直接报错。

### 订阅源全部失效
通知用户，建议检查网络或更换源。不要生成空白日报。

### 网络能力受限
- 无法访问 `plink.anyfeeder.com` 时：让用户手动提供 RSS 链接，继续后续流程
- 无法抓取外网 RSS 时：保留本次配置修改，但终止生成并给出失败原因

### 配置文件异常
- `profile.json` / `subscriptions.json` 不存在：自动创建默认结构并进入引导
- JSON 损坏或字段缺失：尽量修复；无法修复时重建并提示用户确认
- 活跃订阅为空：先引导添加订阅，再允许生成日报

### 路径与平台兼容
- 优先使用 `profile.output_dir`；为空则使用当前工作区
- 输出路径允许 Windows / macOS / Linux 格式，不强制写死盘符
- 写文件前确保目标目录存在，不存在则先创建

### 用户想临时加/减板块
- "今天不要体育板块" → 本期跳过该分类，不影响 subscriptions.json
- "今天加一个 GitHub Trending" → 按列表样式临时添加，不写入订阅

### 用户想修改报纸名
直接更新 `profile.json` 中的 `newspaper_name` 和 `file_prefix`。

### 用户想调整内容量/篇幅
触发词："调整篇幅"、"文章多一点/少一点"、"日报太长了/太短了"

1. 如果用户给了具体数字（如"20 篇"）→ 直接更新 `layout.total_articles`
2. 如果用户说了偏好（如"简洁一点"）→ 映射到对应模式更新 `layout`
3. 也可以临时生效："这次多一点内容" → 仅本期增加，不改配置
4. 更新后提示用户新配置

### 用户提供了自定义 RSS 链接
1. 尝试访问该链接
2. 验证是否返回合法的 RSS/Atom XML
3. 如果有效，询问分类和显示名称后加入订阅
4. 如果无效，告知用户并建议检查链接
5. 安全限制：拒绝 `file://`、`localhost`、`127.0.0.1`、`0.0.0.0`、`::1` 以及内网地址（如 `10.x.x.x`、`192.168.x.x`、`172.16-31.x.x`）

## RSS 源发现

当需要为用户查找 RSS 源时：

1. **首选来源：** `https://plink.anyfeeder.com/` — 中文 RSS 源聚合站点
2. 访问该站点，按用户兴趣领域筛选可用源
3. **⚠️ 重要：** plink 页面上，名称前带有 emoji 错误标记（如 ❌、❎、⚠️ 等）的 RSS 源，表示已有大量用户反馈其无法访问。**必须跳过这些源，不要推荐给用户，也不要尝试抓取。** 只推荐名称前无任何错误 emoji 标记的正常源
4. 如果用户需要的领域在 plink 上找不到，可以通过网络搜索 `"{领域}" RSS feed` 来寻找

**plink.anyfeeder.com 主要分类映射：**

| 用户兴趣 | plink 分类 | 推荐源（优先） |
|---------|-----------|--------------|
| 实时新闻 | 新闻 | 喷嚏图卦、南方周末、界面新闻 |
| 科技 | 科技 | Solidot、36氪、cnBeta、少数派、虎嗅 |
| 财经 | 财经 | 财富中文网、界面商业、经济日报 |
| 游戏 | 科技 | 机核、游研社 |
| 知识 | 知识 | 知乎日报、观止·每日一文 |
| 编程 | 编程 | （注意：该分类下很多源带错误标记，务必过滤后再推荐） |
| 外媒 | 外国媒体 | 华尔街日报中文、纽约时报中文、BBC |
| 英文新闻 | News | BBC、TIME、Business Insider |
| 英文科技 | Technology | Ars Technica、TechCrunch |
