# 收工总结技能

每日工作结束时，扫描当天对话内容，自动识别值得沉淀的经验并写入知识库，同时输出简洁的工作小结。

---

## 脚本分工

> **脚本处理**：解析状态文件，找出有 blockId 但未确认打勾的已完成任务（`scripts/check_pending_ticks.py`）
> **AI 处理**：执行 `blocks_update` MCP 打勾、扫描对话内容、知识库写入、evolve

```bash
# Step 0 自动化：检查待打勾任务
python3 scripts/check_pending_ticks.py <workspace>/aiworkspace/daily_task_state.md
# 输出 pending_ticks 列表，AI 逐一执行 blocks_update
```

---

## 工作流

### Step 0：Craft 打勾检查

收工前，先检查状态文件是否有已完成但未在 Craft 打勾的任务：

```
状态文件路径：<Workspace Path>/aiworkspace/daily_task_state.md
```

读取状态文件中「✅ 已完成」列表，逐一确认每条任务是否有对应的 blockId：
- **有 blockId 且未确认打勾**：立即执行 `blocks_update` 将 `- [ ]` 改为 `- [x]`
- **已确认打勾**：跳过
- **无 blockId**（如场景 B 直接告知任务且用户说「不用记」）：跳过
- **状态文件不存在或无已完成任务**：跳过此步骤

完成后才进入 Step 1。

### Step 1：扫描当天对话

回顾本次会话的完整内容，识别以下类型的有价值内容：

**值得记录的信号**：
- 解决了一个 bug，且根因不显而易见
- 发现了一个之前不知道的技术细节或规律
- 踩了一个坑，或走了弯路后找到了正确方向
- 某个结论/方案在对话中被反复提及或修正

**不值得记录的信号**：
- 纯粹的功能开发（没有踩坑）
- 简单的代码修改（空值判断、typo 等）
- 与业务逻辑强绑定、无法复用的内容
- 当天已经通过其他触发点（bugfix/git-commit）记录过的内容

### Step 2：输出收工小结

用简洁的格式告知用户今天的情况：

```
📋 今日小结

✅ 完成的事：
- [一句话描述，不超过 20 字]
- ...

💡 发现有 N 件事值得写入知识库：
1. [标题] — [一句话说明为什么值得记录]
2. ...

📭 无值得记录的内容（今天没踩坑，好事）
```

如果有值得记录的内容，询问用户：
> 「是否现在写入知识库？说「全记」自动处理所有条目，或指定序号单独记录。」

### Step 3：执行知识库写入

根据用户回复：

- **「全记」或「都记」**：按顺序逐条执行 knowledge-collector，每条完成后继续下一条
- **「记 1」/ 「记第 2 条」**：只执行指定序号的条目
- **「不用」/ 「跳过」**：跳过，结束

执行时读取 `/Users/bryanpeng/.claude/skills/knowledge-collector/SKILL.md` 并遵循其完整流程（含去重检查）。

### Step 4：触发进化（evolve）

知识库写入完成（或跳过）后，**自动触发 `evolve` 技能**，无需用户开口：

读取 `/Users/bryanpeng/.claude/skills/evolve/SKILL.md` 并执行完整进化流程：
- 扫描对话，识别可更新到 Skill 或 CLAUDE.md 的内容
- 展示更新方案，等待用户确认
- 用户确认后执行更新

### Step 4.5：提交开发工具变更（devtools-commit）

evolve 完成后，**自动触发 devtools-commit 技能**，无需用户开口：

读取 `/Users/bryanpeng/.claude/skills/devtools-commit/SKILL.md` 并执行完整提交流程，将当天对 `~/.claude`（skills/agents/knowledge）及 cs 框架仓库的所有变更提交并推送到远端。

### Step 5：收工确认

所有操作完成后，简短告别：

```
👋 收工！今天写入了 N 条记录。
知识库已更新，明天继续。
```

如果没有写入任何内容：
```
👋 收工！今天没有新的踩坑记录，干净利落。
```

## 注意事项

- **不强迫记录**：Step 2 判断「无值得记录内容」时，直接跳过 Step 3，不打扰用户
- **evolve 始终执行**：Step 4 的进化步骤无论 Step 3 是否写入都必须执行，不可跳过
- **避免重复触发**：如果当天某个问题已被 bugfix/git-commit 自动触发过 knowledge-collector，wrap-up 扫描时应识别并跳过（通过去重检查机制保障）
- **小结要简洁**：「完成的事」每条不超过 20 字，列表不超过 5 条，不写废话
- **判断要克制**：宁可漏记，不要滥记 —— 只有「下次遇到同类问题能直接用上」的结论才值得记录
