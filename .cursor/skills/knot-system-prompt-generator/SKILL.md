# Knot System Prompt Generator

读取 Knot Skill 的内容，为其生成适合在 Knot 定时任务或 Agent 配置中使用的 System Prompt。

---

## Step 1：收集信息

### 1.1 确定目标 Skill

从用户输入或当前对话上下文中获取：

- **Skill 路径**：如 `~/.claude/skills/bugly-version-report/`
- **Skill 名称**：如 `bugly-version-report`（若无路径则在 `~/.claude/skills/` 下查找）

若两者均未提供，询问用户：
```
请告诉我要为哪个 Skill 生成 System Prompt？可以提供路径或名称。
```

### 1.2 读取 Skill 内容

按顺序读取以下文件（存在则读，不存在跳过）：

1. `SKILL.md` — 功能描述、使用方式、输出示例（**必读**）
2. `main.py` / `index.py` / `*.py` — 核心逻辑，了解实际做了什么、返回什么
3. `requirements.txt` — 依赖（了解技术栈）

**重点提取：**
- Skill 的 `name`（即 Knot 中的 `display_name`）
- 这个 Skill 做什么（一句话概括）
- 输入参数：有哪些参数？必填/选填？默认值？
- 输出内容：返回什么结构？有几个部分？
- 内嵌的阈值、告警规则（若有）
- 可能的错误场景（网络超时、Token 失效、数据为空等）
- 领域背景：涉及哪些专业术语、业务指标、判断逻辑？

### 1.3 检索知识库

从 Skill 内容中提取 2-5 个关键词（领域术语、产品名、技术栈），按照 `knowledge-retriever` 技能的流程执行知识库检索。

从检索结果中提取与该 Skill 相关的：
- **领域术语解释**（如「FOOM」「ANR」「campType」等）
- **业务判断标准**（如阈值、告警规则、正常/异常定义）
- **注意事项 / 已知坑点**（如「不支持启动速度」「环境不匹配导致配置不下发」）
- **上下游关联**（该 Skill 依赖哪些系统，输出会被谁消费）

若知识库无命中，直接基于 Skill 文件本身的信息生成，并在输出时注明「知识库暂无相关记录」。

### 1.4 询问补充信息（若需要）

读取完文件后，若以下信息无法从文件中确定，主动询问：

```
我已读取了 <skill-name> 的内容，有几个问题确认一下：

❓ 1. 这个定时任务的角色是什么？（如「质量日报助手」「告警分析助手」）
❓ 2. 输出格式有什么偏好？（如：表格 / 列表 / 简洁摘要）
❓ 3. 有没有需要特别强调的业务背景？（如阈值标准、重要指标的含义）
```

若从上下文已能推断，则跳过询问，直接生成并在生成后说明推断依据。

---

## Step 2：生成 System Prompt

基于收集的信息，生成包含以下六个部分的 System Prompt：

### 结构模板

```
你是 {产品名} 的 {角色名称}。

## 你的职责

每次运行时，你需要完成以下工作：
1. 调用 `{skill-name}` 技能，{一句话说明获取什么数据}
2. 解读{技能}返回的内容，识别需要关注的{异常/问题/指标}
3. 输出一份{简洁/详细}的{报告类型}摘要
4. {如有超标/异常}，给出建议的处理方向

## 技能调用方式

调用 `{skill-name}` 技能（display_name: {skill-name}），{无需传入任何参数，直接调用即可 / 传入以下参数：xxx}。

技能会自动：
{- 列出技能的核心动作，每条一行}

## {告警阈值 / 判断标准}（若有）

{以表格或列表形式列出阈值/规则}

## 输出格式

技能调用完成后，按以下格式输出：

---
{完整的输出模板，含占位符、emoji、表格等}
---

## 异常处理

- 如果技能返回错误（{列出常见错误原因}），{说明如何处理}
- 如果数据返回为空或格式异常，{说明如何处理}
- 不要编造任何数据，所有内容必须来自技能返回的真实结果

## 背景知识

{列出理解和解读技能输出所需的领域知识，每条用粗体标注术语}
```

### 生成原则

- **角色定义**：根据 Skill 的领域（Bugly → 质量日报助手，伽利略 → 监控分析助手，etc.）自动推断
- **输出格式**：参考 SKILL.md 的「输出示例」章节，若没有则根据业务场景设计一个合理的模板
- **阈值**：如果代码中硬编码了阈值（如 `Crash 率 > 0.05%`），必须提取并写入 System Prompt
- **异常处理**：覆盖代码中所有 `return f"[错误] ..."` 的场景
- **背景知识**：**优先使用 Step 1.3 从知识库检索到的内容**，补充用户理解输出所需的领域术语（如指标定义、阈值含义、业务规则）；知识库无命中时，从 Skill 文件本身推断。不需要解释 Skill 内部实现细节。

---

## Step 3：输出与确认

生成完成后，以 markdown 代码块输出完整 System Prompt：

```
以下是为 `{skill-name}` 生成的 System Prompt，可直接粘贴到 Knot 定时任务的 Prompt 字段：

---
{完整 System Prompt 内容}
---

**生成依据：**
- 角色名称：从 {来源} 推断
- 阈值：从代码 main.py 第 {X} 行提取
- 输出格式：参考 SKILL.md「输出示例」章节设计
- 背景知识：来自知识库《{文章名}》/ 知识库暂无命中，基于 Skill 文件推断
- 异常处理：覆盖了代码中的 {N} 种错误场景

如需调整，请告诉我（如：修改输出格式、增加背景知识、调整阈值等）。
```

若用户有修改意见，按反馈迭代更新，直到满意为止。

---

## 注意事项

- **不修改原 Skill 文件**：本技能只生成文本，不写入任何文件
- **Knot 的特殊性**：Knot 定时任务的 Prompt 即 System Prompt，无需区分「系统/用户」层级，直接写指令即可
- **保持精简**：System Prompt 不要重复 Skill 内部的实现细节，聚焦「Agent 需要做什么、怎么判断、怎么输出」
- **迭代友好**：每次修改后，输出完整的最新版本，而不是 diff 片段，方便用户直接复制
