# Ralph Loop — 代码修改自愈循环

## 核心概念

Ralph Loop 是解决「单次 Prompt 输出不稳定」的工程方法，通过自主迭代机制让 AI 的代码修改向确定性收敛。

### 三要素

| 要素 | 说明 |
|------|------|
| **同一 Prompt** | 每轮使用相同的任务指令。失败时将错误信息**追加**到上下文，但核心 Prompt 不变——让 AI 在同一目标下自我修正，而非人为干预改变方向 |
| **明确退出条件** | 预先声明「成功」的判定标准，在循环开始前对用户可见 |
| **最大重试次数** | 默认 3 次，防止无限循环；达到上限后报告失败并建议人工介入 |

---

## 如何被其他 Skill 调用

在任何 Skill 完成「代码实现」步骤后，用以下方式衔接 Ralph Loop：

```
> 📍 调用 Ralph Loop
> 读取 /Users/bryanpeng/.claude/skills/ralph-loop/SKILL.md
> 传入参数：
>   Prompt: <本次代码修改的任务描述，一句话>
>   退出条件: <见下方类型表>
>   最大重试: <N，默认3>
```

---

## 退出条件类型

| 类型 | 触发场景 | 验证工具 | 通过标准 |
|------|---------|---------|---------|
| `compilation` | **iOS/OC/Swift 代码修改（默认）** | xcode-tools `BuildProject` | `errors` 列表为空 |
| `dart-analyze` | Flutter/Dart 代码修改 | `flutter analyze` (Shell) | 0 errors |
| `spec-checker` | 伽利略埋点实现 | `galileo-spec-checker` skill | 所有检查项通过 |
| `custom` | 自定义场景 | 用户指定验证逻辑 | 用户指定标准 |

## 执行流程

### Step 0：声明三要素（每次 Loop 开始时必须输出）

```
🔄 Ralph Loop 启动
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📌 Prompt（固定）：<任务描述>
✅ 退出条件：<类型 + 具体标准>
🔁 最大重试：<N> 次
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Step 1：执行

根据当前上下文（= 原始 Prompt + 历次失败的错误信息）实现或修正代码。

**上下文结构**：
```
[原始 Prompt]
---
[第1次错误信息（如有）]
[第2次错误信息（如有）]
...
```

### Step 2：验证（按退出条件类型执行）

#### 类型：compilation（iOS 默认）

```
1. 调用 xcode-tools XcodeListWindows 获取 tabIdentifier
2. 调用 xcode-tools BuildProject
3. 检查返回的 errors 列表：
   - 为空 → ✅ 通过
   - 非空 → ❌ 失败，将 errors 内容追加到上下文，进入重试
```

#### 类型：dart-analyze

```
1. Shell: cd flutter_module && flutter analyze --no-pub 2>&1
2. 检查输出：
   - 含 "No issues found" → ✅ 通过
   - 含 error 行 → ❌ 失败，将错误列表追加到上下文
```

#### 类型：spec-checker

```
1. 读取并执行 galileo-spec-checker skill
2. 检查 checker 报告：
   - 所有项通过 → ✅ 通过
   - 有未通过项 → ❌ 失败，将未通过项追加到上下文
```

#### 类型：custom

```
执行用户指定的验证逻辑，按用户定义标准判断通过/失败
```

### Step 3：判断继续或退出

```
if 验证通过:
    → 输出成功报告，退出 Loop
elif 当前轮次 < 最大重试次数:
    → 将错误信息追加到上下文
    → 当前轮次 + 1
    → 回到 Step 1（使用同一 Prompt + 累积上下文重新执行）
else:
    → 输出失败报告，建议人工介入，退出 Loop
```

## 注意事项

- **Prompt 固定是核心**：失败时只追加错误上下文，绝不修改原始 Prompt 或改变任务目标
- **上下文累积是关键**：每轮失败的错误信息都要保留，让 AI 能从全局角度分析模式
- **3次失败须人工介入**：不得继续盲目重试，必须报告并停下来
- **退出条件须在 Step 0 声明**：不允许执行中途改变退出标准
