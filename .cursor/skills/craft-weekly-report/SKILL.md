# Craft 周报生成技能

从用户提供的 Craft 文档中，提取所有已完成的任务项，并按照标准格式整理输出周报。

## 工作流程

### 第一步：获取文档

用户提供文档名称（或文档 ID）：
- 如果是文档名称：使用 `documents_search` 工具搜索，取第一个匹配结果的 `documentId`
- 如果是文档 ID：直接使用

```
MCP Server: user-craft
Tool: documents_search
参数: { "include": "<文档名称>" }
```

### 第二步：读取文档内容

使用 `blocks_get` 读取完整文档内容：

```
MCP Server: user-craft
Tool: blocks_get
参数: { "id": "<documentId>", "format": "markdown" }
```

如果返回了 `nextCursor`，继续分页读取直到获取全部内容。

### 第三步：提取已完成任务

扫描文档中所有标记为 `[x]` 的任务项（已完成），忽略 `[ ]` 未完成项。

**归类规则**：
- 使用文档中的**一级编号标题**（如 `1. 多游保障专项`、`2. Bugly质量评分`）作为分类依据
- 若某个分类下没有任何已完成任务，**跳过该分类，不输出**
- 若文档没有明确分类标题，则根据任务内容的主题自动归类（如：伽利略、Bugly、染色、其他）
- **若某个小节（标题或名称）叫做「提升」，则该小节属于个人学习提升内容，跳过整个小节，不统计进周报**

### 第四步：整理输出

**输出格式**（严格按照此格式）：

```
**分类名**：

1. 任务描述1
2. 任务描述2
3. 任务描述3

**分类名**：

1. 任务描述1
...
```

**格式规则**：
- 分类名加粗，后跟中文冒号 `：`
- 每个分类下使用数字编号列表
- 分类之间空一行
- 每个分类最多保留 **5 条**，若超过则优先保留最重要/信息量最大的条目
- 任务描述保留核心信息，去除口语化表述，但不要过度压缩导致信息丢失

## 输出示例

**伽利略**：

1. P0 和 P1 告警 oncall 闭环建设，相对稳定；重新整理 oncall 分组，按项目组规范
2. Android 接入过程中问题修改，Flutter 容器上报修改
3. 新增单点报错上报告警建设和调试
4. 天同比 crash 调整至 200% 阈值；crash 暴增告警暂停
5. App 退出原因分析细化更新；事件关联分析增加正式环境联动

**Bugly**：

1. 3月6日晚 crash 率天同比突破 80% 问题分析，原因为首页视频问题触发量暴增

**其他**：

1. 染色 SDK 升级，处理跳转 AppStore 时被挂起的保活风险
2. 染色接口调整，补全必传参数并增加上报
3. iOS 证书更新

## 注意事项

- 只输出已完成的任务（`[x]` 标记）
- 未完成（`[ ]`）的任务**一律不出现**在结果中
- **标题或名称为「提升」的小节整体跳过，不统计进周报**（属于个人任务，不对外汇报）
- 如果文档找不到，告知用户并请求确认文档名称
- 如果文档中没有任何已完成任务，告知用户
