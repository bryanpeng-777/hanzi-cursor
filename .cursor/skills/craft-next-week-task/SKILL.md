# Craft 下周任务创建技能

在 Craft 「贡献与付出（c）」文件夹中，快速建立下周任务结构，并将本周文档自动迁移过去。源文件夹下所有文档（含流程设计）统一迁移到新 MMDD 文件夹，迁移规则根据文档类型自动区分。

## 固定信息

- **目标父文件夹**：`贡献与付出（c）`，ID 为 `986AC3A8-4EA4-408B-8D9B-CC7620BEDFFB`
- **文件命名规则**：以当前周一日期 `MMDD` 作为前缀，例如当前周一是 4 月 20 日，则前缀为 `0420`
- **文件夹命名**：`0420`（纯日期）
- **所有文档**：当前周文件夹下的**所有文档**（包含工作任务文档和流程设计文档），全部创建到新文件夹下
- **文档类型识别**：文档标题以 `流程设计` 结尾的视为「流程设计文档」，其余视为「工作任务文档」

## 脚本分工

> **脚本处理**：计算下周一日期前缀、从本周 markdown 文件提取未完成任务（`scripts/next_week_task.py`）
> **AI 处理**：调用 Craft MCP 创建文件夹/文件、写入内容、验证

```bash
# 只计算日期前缀
python3 scripts/next_week_task.py

# 同时提取当前周未完成任务
python3 scripts/next_week_task.py <current_week.md>

# 指定基准日期
python3 scripts/next_week_task.py --date 2026-04-14
```

脚本输出 JSON，AI 读取后直接使用 `prefix`、`files_to_create`、`uncompleted_content` 执行 Craft MCP 调用。

## 工作流程

源文件夹下所有文档统一迁移到新 MMDD 文件夹，迁移规则按文档类型自动区分：

| 文档类型 | 识别方式 | 迁移规则 |
|---------|---------|---------|
| 工作任务文档 | 标题**不以**「流程设计」结尾 | 只迁移未完成 `[ ]` 项 |
| 流程设计文档 | 标题**以**「流程设计」结尾（如 `0427流程设计`） | 全量复制，所有任务重置为 `[ ]` |

所有文档（含流程设计）的目标位置均为 `贡献与付出（c）` > `MMDD新` 文件夹。

### Step 1：确定日期

根据当前系统日期，计算**本周**（或用户指定周）对应的周一日期，格式化为 `MMDD`。

- 若今天是周一（新一周刚开始），则"当前周"= 今天所在周，"新建周"= 今天所在周（即创建本周文件，从上周迁移）
- 若今天是周二到周日，则"当前周"= 今天所在周，可按需创建"下周"文件

> 实际执行时：询问用户「我来从哪个文件夹迁移？（如 0413）」，直接用用户告知的前缀作为源，自动计算目标前缀（源+7天）。

### Step 2：获取源文件夹名

询问用户当前周（源）的文件夹名：

> 「请告诉我要从哪个文件夹迁移？（如 0413）」

拿到后，自动计算目标前缀：源日期 + 7 天，格式化为 `MMDD`。

### Step 3：读取当前周所有文档内容

1. 通过 `folders_list` 在 `贡献与付出（c）`（ID：`986AC3A8-4EA4-408B-8D9B-CC7620BEDFFB`）的子文件夹中，匹配源文件夹名（如 `0427`）得到文件夹 ID
2. 调用 `documents_list`，传入该文件夹 ID，列出其中**所有文档**（包括工作文档和流程设计文档）
3. 对每个文档**循环**调用 `blocks_get`，`id: "<文档ID>"`, `format: "markdown"`，读取全文（分页读取直到无 `nextCursor`；遇到 `CURSOR_INVALID` 从头重读）
4. 同时根据文档标题判断类型：标题以 `流程设计` 结尾的为「流程设计文档」，其余为「工作任务文档」

> ⚠️ **关键**：源文件夹下有几个文档，目标就创建几个同名（替换前缀）文档，一一对应，不遗漏。包括流程设计文档。

### Step 4：提取迁移内容

对每个文档，根据类型应用对应规则：

**工作任务文档（只提取未完成）**：

提取所有 `- [ ]` 开头的行（包括有缩进的子项 `  - [ ]`）。保留原有分组标题，维持文档结构层次。

迁移规则：
- `- [ ]` 父项 → 迁移，其所有子项（无论是否完成）一并迁移
- `- [x]` 父项 → 不迁移，其所有子项跟随不迁移

**流程设计文档（全量复制并重置）**：

提取**所有任务行**（包括 `- [x]` 和 `- [ ]`），并将所有 `- [x]` 统一替换为 `- [ ]`。保留原有分组标题和文档结构，所有任务重置为未完成状态。

> **转换规则**：只替换任务状态标记，不修改任务文字内容和缩进层级。

### Step 5：创建新文件夹

调用 `folders_create`，在 `贡献与付出（c）` 下创建新文件夹：

```json
{
  "folders": [
    {
      "name": "<MMDD新>",
      "parentFolderId": "986AC3A8-4EA4-408B-8D9B-CC7620BEDFFB"
    }
  ]
}
```

记录返回的新文件夹 ID。所有文档（含流程设计）均放入此文件夹。

### Step 6：创建新文件

对源文件夹中的**每一个**文档，创建对应的新文档（名称 = 目标前缀 + 原文档名去掉源前缀的部分）：

- `0427-camp` → `0504-camp`
- `0427流程设计` → `0504流程设计`（流程设计文档同样放入新 MMDD 文件夹）

```json
{
  "documents": [{"title": "<MMDD新><后缀>"}],
  "destination": { "folderId": "<新文件夹ID>" }
}
```

直接在 `documents_create` 时指定 `destination.folderId`，无需额外 `documents_move`。

### Step 7：写入内容

对每个新建文档，根据类型写入对应内容：

- **工作任务文档**：调用 `markdown_add`，`position: "end"`，写入 Step 4 提取的未完成项内容
- **流程设计文档**：调用 `markdown_add`，`position: "end"`，写入全量复制+重置后的内容

> ⚠️ **关键**：`markdown_add` 必须使用 `pageId` 参数（不是 `documentId`），传入文档 ID。若漏传 `pageId`，内容会写入错误位置且文档保持空白。

### Step 8：汇报结果

完成后，向用户展示简要汇报：

```
📁 贡献与付出 > <MMDD新>：
  ✅ 新建文件夹：<MMDD新>
  ✅ <工作文件名1>：迁移 N 条未完成项
  ✅ <工作文件名2>：迁移 M 条未完成项
  ... （所有工作任务文档，一一列出）
  ✅ <MMDD新>流程设计：全量复制 K 条任务，已全部重置为未完成状态
```

## 注意事项

- **不要删除或修改原文件**：只读取，不做任何写入或移动操作
- **文档数量动态**：源文件夹有几个文档就创建几个，不能遗漏（含流程设计文档）
- **文件名替换规则**：目标文件名 = 目标前缀 + 原文件名去掉源前缀的部分
  - 带连字符的工作文档：`0427-camp` → `0504-camp`
  - 无连字符的流程文档：`0427流程设计` → `0504流程设计`
- **文档类型自动识别**：标题以 `流程设计` 结尾 → 流程设计文档（全量复制+重置）；其余 → 工作任务文档（只迁移未完成项）
- **工作任务迁移规则**：
  - 保留原文档分组标题，只删去已完成的 `[x]` 条目
  - 子列表项：若父项未完成，其所有子项（无论是否完成）也一并迁移；若父项已完成，子项跟随父项不迁移
- **流程设计迁移规则**：
  - 保留原文档所有分组标题和结构
  - 所有任务行（含 `[x]` 和 `[ ]`）全部复制，`[x]` 统一替换为 `[ ]`
  - 子列表项完整保留，状态同样全部重置为 `[ ]`
- **所有文档统一放入新 MMDD 文件夹**：包括流程设计文档，不再单独放到 `Life-个人 > 流程` 文件夹
- **documents_create 直接指定 destination**：创建时传入 `folderId` 参数，无需事后再调用 `documents_move`
- **markdown_add 必须用 pageId**：写入内容时参数名是 `pageId`，不是 `documentId`。传错参数会导致内容写到错误位置，文档看起来是空的
- **中文转义**：传递 markdown 内容时，确保中文字符正确编码，不需要额外转义
