# 知识库收录技能

将任意来源的知识提炼为结构化文章，存储到 Craft 知识库中。每篇文章围绕一个主题，可随新知识持续更新。索引提供轻量检索入口。

## 核心原则

- **一个主题一篇文章**：知识围绕主题聚合，而不是按时间流水
- **文章是活的**：新知识可以合并到已有文章，而不是只能新建
- **AI 自行判断**：新建 vs 更新由 AI 根据索引匹配度决定
- **AI 友好格式**：文章以声明式、条件式写法组织，方便 AI 高效消费
- **双写机制**：每次操作 = 文章（完整内容）+ 索引一行（轻量检索）

## 工作流

### Step 0：选择写入目标（通用 / camp / KingGuard）

**必须先于读索引执行**。结合当前工作区目录名与用户表述做默认推荐，并 **一句话向用户确认**（自动触发且上下文明确时可省略口头确认，但须在预览里写清目标库）：

| 启发规则 | 默认写入 |
|----------|----------|
| 知识仅关乎 KingGuard（Unity、`GameplayManager`、`TowerModel`、本仓库关卡/敌人等） | **KingGuard** |
| 知识关乎王者营地 App、**伽利略**、**Bugly**（含 Agent/Token/告警与崩溃排查链路）、flutter_module / social-ios 等 | **camp** |
| 可复用到任意项目（Git、纯语言/工具、与业务仓库无关的 Agent 方法等） | **通用** |
| 当前 `cwd` 为 `KingGuard` 且用户未说明 | 默认 **KingGuard**，若明显是通用技能可改 **通用** |
| 用户明确说「记到通用 / 记到营地 / 记到 KingGuard」 | 以用户为准 |

选定目标后，记 `writeTarget ∈ {general, camp, kingguard}`，后续 **索引 pageId** 与 **子文件夹 folderId** 均查本节映射表中对应库。

### Step 0.5：读索引 + 去重/匹配检查

提取当前知识的 2-5 个核心关键词，读取 **选定目标库** 的《知识库索引》：

```
blocks_get({
  id: "<该目标的索引 pageId，见上表>",
  format: "markdown"
})
```

**不要**默认扫旧库索引；仅当用户要求「对照旧库去重」时再读 `bab47845-439d-e239-4ac7-47914da657cc`。

**如果 Craft MCP 调用失败**：降级跳过去重，直接进入 Step 1，最终输出时告知用户「去重检查因 Craft 不可达而跳过」。

扫描索引表格的「关键词」和「别名」列，判断是否有已有相关文章。记下匹配结果，供 Step 3 使用。

---

### Step 1：理解并提炼知识

根据知识来源类型，采用不同的提炼策略：

| 来源 | 提炼方式 |
|------|---------|
| 用户直接描述 | 从对话中提取核心知识点 |
| 文章/文档 | 提取关键结论、规则、模式 |
| 代码模块分析 | 总结模块职责、接口、调用关系、注意事项 |
| 库/框架学习 | 提取 API 用法、最佳实践、常见陷阱 |
| bug 修复对话 | 提取问题现象、根因、解决方案、防范措施 |

---

### Step 2：自动判断知识类型 + 分类 + 关键词 + 别名 + 时效性

**知识类型判断**：
- 若来源是 bug 修复对话、用户描述的是踩坑/错误经验 → 分类为「错误经验」，使用错误经验文章模板
- 否则 → 使用通用知识文章模板

**关键词**：2-5 个，覆盖技术栈、模块名、核心概念

**别名**：关键词的同义词、英文/中文对照、缩写、相关术语。用于提高检索召回率。
- 示例：关键词 `ZTSDK, 初始化`，别名 `游戏SDK, ZTGAME, setup, init, 启动`

**时效性自动推断**：

| 时效性 | 推断规则 | 示例 |
|--------|---------|------|
| `长期有效` | 架构设计、业务规则、团队约定、编程范式；内容不涉及具体版本号 | "Service 统一通过 Manager 注册" |
| `版本相关(xxx)` | 内容中出现具体版本号、描述特定 SDK/库的 API、来源是代码分析且代码可能被重构 | "Flutter 3.16 的 PlatformView 行为" |
| `待验证` | 来源是网络文章且未经代码验证、AI 推断的不确定结论、用户口头描述未附代码佐证 | "某博客说 WKWebView 在 iOS 18 会..." |

在预览中展示推断结果和依据，用户可在确认环节修改。

---

### Step 3：判断拆分

评估知识覆盖的子主题数量：
- **子主题 ≤ 3 个** → 一篇文章
- **子主题 > 3 个** → 建议拆分，展示拆分方案供用户确认

```
示例输出：
「这个主题涉及 4 个相对独立的子主题，建议拆分为：
 ① 《TRouter 注册与 Scheme 解析》
 ② 《营地 Flutter-Native 路由桥接》
 ③ 《营地深链接处理机制》
 还是你希望合并为一篇？」
```

---

### Step 4：判断新建 vs 更新

基于 Step 0 的索引匹配结果：

| 匹配情况 | 判断标准 | 操作 |
|---------|---------|------|
| **无匹配** | 关键词无重叠或主题完全不同 | → 新建文章 |
| **高度匹配** | 关键词 ≥ 3 个重叠，且主题相同 | → 更新已有文章 |
| **部分匹配** | 关键词 1-2 个重叠，主题有交叉 | → 询问用户 |

**部分匹配时的询问格式**：
```
发现相关文章：《ZTSDK 初始化与生命周期》
关键词重叠: ZTSDK, 初始化
当前新知识主题: ZTSDK 回调机制

请选择：
A) 合并到已有文章（作为新章节补充）
B) 新建独立文章
```

#### 索引行格式

```markdown
| {序号} | {分类} | {关键词} | {别名} | {知识主题} | {摘要，3-5个核心结论压成一句话} | [[{文章标题}]] | {时效性} | {YYYY-MM-DD} |
```

**摘要字段是最重要的**：必须包含最核心的可操作结论，AI 不读文章也能获得 80% 的信息。

### Step 6：预览确认

展示给用户：

1. **操作类型**：新建文章 / 更新已有文章
2. **知识类型**：通用知识 / 错误经验
3. **文章标题**
4. **索引行预览**
5. **时效性**（及推断依据）
6. **文章内容预览**

询问用户是否确认，或需要调整。

> 如果是自动触发（由 bugfix / git-commit / wrap-up 调用），且索引为空（首次使用），直接跳过去重检查。自动触发时仍展示预览供用户确认。

### Step 7：执行写入 Craft

#### 新建文章

1. 根据 **Step 0 的 writeTarget** 与分类，查找 **该库** 的 folderId（见「各库分类 → folderId 映射」），调用 `documents_create` 在对应子文件夹下创建新文档：

```
documents_create({
  documents: [{ title: "文章标题" }],
  destination: { folderId: "对应分类的子文件夹 folderId" }
})
```

2. 调用 `markdown_add` 写入文章内容：

```
markdown_add({
  markdown: "[文章内容]",
  position: "end",
  pageId: "新文档 ID"
})
```

3. 调用 `markdown_add` 将索引行追加到 **选定目标库** 的《知识库索引》：

```
markdown_add({
  markdown: "| {序号} | {分类} | {关键词} | {别名} | {主题} | {摘要} | [[{标题}]] | {时效性} | {日期} |",
  position: "end",
  pageId: "<writeTarget 对应索引 pageId>"
})
```

序号从 **该库** 现有索引的最大序号 +1。如无法确定，用 `?` 占位。**不要**默认写回旧库索引，除非用户明确要求写旧库。

#### 更新已有文章

1. 调用 `blocks_get` 读取已有文章全文
2. 分析新知识与已有内容的关系：
   - 新的子主题 → 用 `markdown_add` 在合适位置添加新章节
   - 已有子主题的补充 → 在对应小节末尾追加
   - 矛盾内容 → 展示给用户确认以哪个为准
3. 在「变更记录」追加一行
4. 更新「关键结论」部分（如有新结论）
5. 更新索引中该行的「摘要」和「更新日期」（读取索引找到对应行，用 `blocks_update` 修改）

---

### Step 8：关联链接

扫描索引，找出与当前文章关键词有 1 个以上重叠的其他文章：
- 在当前文章的「相关知识」部分添加链接
- （可选）在被关联文章中也添加反向链接

---

### Step 9：完成确认

告知用户：
- 操作类型：新建 / 更新
- 文章标题和位置：`Growth-AI-{通用|camp|KingGuard}知识库 / {分类} / {文章标题}`
- 索引已更新
- 可通过关键词 `xxx` 在知识库中检索到
- 关联了 N 篇相关知识（如有）

## 注意事项

- **默认不读、不写旧库**（`bab47845` / `b448f10b`）：去重与索引追加只针对 Step 0 选定的通用 / camp / KingGuard 库，除非用户明确要求操作旧库
- 如果当前对话内容不足以形成有价值的知识，主动向用户询问补充信息
- 代码片段只保留最核心的部分（不超过 30 行），完整代码不需要记录
- **索引行的「摘要」是最重要的字段**：必须包含直接可操作的结论
- **文章的「核心知识」部分使用规则化写法**：前置条件、规则、注意事项，而不是叙事文体
- 新建文章时不要修改已有文章内容
- 更新文章时只追加/修改相关部分，不要重写整篇文章
- 防范措施尽量写成 checklist（`- [ ]`），方便复用
