# 错题集收录技能（已废弃）

从当前对话提炼经验教训，以结构化格式写入 Craft 月度详情文档，并在总索引中登记一条轻量记录，建立可检索的闭环知识库。

## 核心原则

- **双写机制**：每次记录 = 详情文档（完整内容）+ 索引一行（轻量快速检索）
- **从对话中主动提炼**：不要让用户重复描述，读取当前对话自行理解问题和解决方案
- **结构先于内容**：使用固定模板，确保每条记录格式统一，方便 agent 后续检索
- **追加不覆盖**：找到当月文档后追加，而非新建文档（除非本月还没有）

## 工作流

### Step 0：去重检查

**在提炼任何内容之前**，先从当前对话/问题中提取 2-4 个核心关键词，尝试调用 `blocks_get` 读取总索引：

```
blocks_get({
  id: "5fef4a3b-d203-7a19-0f81-d8f5a72a1280",
  format: "markdown"
})
```

**如果 Craft MCP 调用失败**（超时、网络不可达等），**降级处理**：跳过去重检查，直接进入 Step 1，但在最终输出中告知用户「去重检查因 Craft 不可达而跳过，建议后续手动检查是否有重复」。

扫描索引表格，判断是否存在**高度相似**的历史记录（同一根因 + 同一模块）。

**相似度判断标准**：
- 关键词有 2 个以上重叠，且「坑的描述」指向同一根因 → **高度相似**
- 关键词有 1 个重叠，但症状或模块不同 → **低度相似，可继续记录**
- 无重叠 → **无重复**

**处理规则**：

| 情况 | 处理方式 |
|------|---------|
| 高度相似（根因相同） | 停止记录，告知用户已有记录，展示现有条目，询问是否要补充新信息到已有详情 |
| 低度相似（症状不同） | 告知用户发现相似记录，展示后询问：「这是同一个坑的新变体，还是独立的新问题？」由用户决定 |
| 无重复 | 直接进入 Step 1 |

**去重拦截的输出格式**：
```
⚠️ 发现相似历史记录，避免重复写入：

【已有记录】关键词: ZTSDK, 初始化
  坑: ZTSDK 在非主线程调用 init 会导致回调丢失
  结论: ZTSDK 所有初始化必须在主线程执行
  详情: [[2026-03 错题详情]]

请问这次的问题是：
A) 同一个坑（跳过记录）
B) 同一模块的新变体（继续记录，新建条目）
C) 完全不同的问题（继续记录）
```

> 如果是自动触发（由 git-commit / bugfix / wrap-up 调用），且索引为空（首次使用），直接跳过去重检查进入 Step 1。

### Step 1：从对话提炼内容

读取当前对话，识别以下信息：

**提炼要素**：
- 遇到了什么问题？（问题描述）
- 为什么会出现这个问题？（根因分析）
- 怎么解决的？（解决方案 + 关键代码）
- 下次如何避免？（经验教训 + 防范措施）

**内容分类**（选择最匹配的）：
- `代码Bug` — 内存泄漏、crash、逻辑错误
- `架构设计` — 方案选型踩坑、设计模式误用
- `开发流程` — 上线流程、测试遗漏、沟通问题
- `业务理解` — 需求理解偏差、产品逻辑误判
- `工具配置` — Xcode、Flutter、环境配置踩坑
- `性能优化` — 性能问题的根因和优化思路
- `通用经验` — 不属于以上类别的经验总结

**内容标签**（从对话内容推断，1-5 个）：
例：`iOS`, `Flutter`, `内存管理`, `多线程`, `网络`, `UI渲染`, `Galileo`, `TAPD`, `Git` 等

**严重程度**（对业务影响）：
- `高` — 导致线上 crash / 数据问题 / 重大延误
- `中` — 影响开发效率或有隐患
- `低` — 小坑，耗时但无线上影响

### Step 2：生成两份内容草稿

**2A. 详情条目**（写入月度文档）：

```markdown
---

## 📌 [简短标题，20字以内，能概括核心问题]

> **类型**: [分类] | **日期**: YYYY-MM-DD | **严重程度**: [高/中/低]  
> **标签**: `tag1` `tag2` `tag3`

### 问题描述

[清晰描述遇到的问题现象，1-3 句话]

### 根因分析

[为什么会出现这个问题？深挖到根本原因]

### 解决方案

[怎么解决的，包含关键代码片段（如果有）]

### 经验教训

[下次遇到类似情况应该怎么做？有哪些规律？]

### 防范措施

[如何在编码/设计/流程上避免再次踩坑？可以是 checklist]
```

**2B. 索引一行**（追加到总索引表格末尾）：

```markdown
| {序号} | {关键词1}, {关键词2} | {坑的描述，一句话，20字以内} | {可复用结论，一句话，直接可操作} | [[{月度文档标题}]] | {YYYY-MM-DD} |
```

- **关键词**：2-4 个，覆盖技术栈、模块名、症状，用于 AI 检索时匹配
- **坑的描述**：现象，描述出了什么问题
- **可复用结论**：解法/规律，下次遇到直接用，不需要看详情也能行动

### Step 3：向用户展示预览并确认

展示给用户：

1. **错题标题**
2. **索引行预览**（一行表格）
3. **详情内容预览**（折叠展示，告知将写入哪个月度文档）

询问用户是否确认，或需要调整。

### Step 4：在 Craft 中找到或创建月度详情文档

**操作步骤**：

1. 调用 `documents_list` 查找 `Growth-AI-错题集` 文件夹（folderId: `8fc1e9f2-9dcb-f392-9712-76eccdb94afa`）下的当月文档（格式：`YYYY-MM 错题详情`）
   - **如果存在**：获取其 document ID，准备追加
   - **如果不存在**：调用 `documents_create` 新建，destination 使用 folderId `8fc1e9f2-9dcb-f392-9712-76eccdb94afa`，然后写入文档头部：

```markdown
# YYYY-MM 错题详情

> Growth-AI-错题集 错误知识库，本月详情记录。每条记录包含：问题描述、根因、解决方案、经验教训。
> 索引入口：[[错误知识库索引]]

---
```

### Step 5：追加详情条目到月度文档

调用 `markdown_add` 将 Step 2A 的内容追加到月度文档末尾：

```
markdown_add({
  markdown: "[Step 2A 生成的详情内容]",
  position: "end",
  pageId: "月度文档 ID"
})
```

### Step 6：更新总索引

调用 `markdown_add` 将 Step 2B 的索引行追加到总索引文档（pageId: `5fef4a3b-d203-7a19-0f81-d8f5a72a1280`）末尾：

```
markdown_add({
  markdown: "| {序号} | {关键词} | {坑的描述} | {可复用结论} | [[{月度文档标题}]] | {日期} |",
  position: "end",
  pageId: "5fef4a3b-d203-7a19-0f81-d8f5a72a1280"
})
```

> 序号从现有索引表格的最大序号 +1 开始。如无法确定，用 `?` 占位，告知用户手动修正。

### Step 7：完成确认

告知用户：
- 详情已写入：`Growth-AI-错题集 / YYYY-MM 错题详情`（第 N 条）
- 索引已更新：`错误知识库索引`（第 N 行）
- 可通过关键词 `xxx` 在索引中检索到此条记录

## 注意事项

- 如果当前对话内容不足以识别清晰的问题/解决方案，主动向用户询问补充信息
- 代码片段只保留最核心的部分（不超过 30 行），完整代码不需要记录
- 防范措施尽量写成 checklist（`- [ ]`），方便复用
- 追加时不要修改文档已有内容，只在末尾添加
- **索引行的「可复用结论」是最重要的字段**：必须是直接可操作的一句话，不能是描述性的废话
