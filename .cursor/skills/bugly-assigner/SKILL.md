# Bugly Assigner

## Overview

分析 Bugly 异常堆栈（Crash / ANR / FOOM）并智能分配给合适的开发者处理，确保问题能够由最熟悉相关代码的人员解决。

## 脚本分工

> **脚本处理**：从堆栈文本提取文件路径+行号，执行 git log 回溯，输出开发者权重排名（`scripts/git_trace.py`）
> **AI 处理**：解析堆栈图片（若为图片输入）、过滤系统框架层、生成最终分配报告

```bash
# 从 stdin 堆栈文本分析（推荐）
cat stack.txt | python3 scripts/git_trace.py

# 指定具体文件路径
python3 scripts/git_trace.py /path/to/File.swift:123 /path/to/Other.m:456
```

输出 JSON（`ranked_authors` 排名），AI 取 `ranked_authors[0]` 为主责人，结合代码语义确认最终分配。

## 工作流程

### 步骤1: 提取堆栈信息

**如果用户提供图片**：
- 使用Read工具读取图片，识别其中的文本内容
- 提取关键信息：文件路径、行号、类名、方法名、函数签名

**如果用户提供文本**：
- 直接分析文本内容
- 提取相同的堆栈关键信息

**提取的关键信息**：
```
文件路径: /path/to/file.swift:123
类名: ClassName
方法名: methodName
函数签名: ClassName.methodName(params)
模块: 模块名/包名
```

### 步骤2: 分析堆栈结构

从堆栈中识别问题代码的具体位置：

**堆栈分析**：
1. 从下往上分析（通常崩溃点在最上层）
2. 识别用户代码层（过滤系统库、框架库）
3. 定位到最相关的业务代码位置

**输出格式**：
```
分析结果:
  异常位置: [文件路径]:[行号]
  类/方法: [类名].[方法名]
  模块: [模块名]

完整堆栈:
  [堆栈内容]
```

### 步骤3: 查找git提交记录

根据提取的信息，按时间顺序查找git提交：

**查找策略**：
1. 首先查找最近1个月的提交
2. 如果没有，查找最近2个月的提交
3. 如果还没有，继续往前查找（3个月、4个月...）
4. 直到找到有提交记录为止

**匹配方式**：

**方式1: 精确匹配文件路径和行号**
```bash
# 查找修改过该文件的提交
git log --since="1 month ago" --name-only --pretty=format:"%h|%an|%ae|%ad|%s" -- [文件路径]

# 查找在指定行号附近有修改的提交
git log --since="1 month ago" -L [行号],[行号]:[文件路径] --pretty=format:"%h|%an|%ae|%ad|%s"
```

**方式2: 模糊匹配类名或方法名**
```bash
# 在代码中搜索类名/方法名引用
git log --since="1 month ago" -S"[类名/方法名]" --pretty=format:"%h|%an|%ae|%ad|%s"

# 搜索关键词
git log --since="1 month ago" --grep="[类名/方法名]" --pretty=format:"%h|%an|%ae|%ad|%s"
```

**方式3: 模块级别匹配**
```bash
# 查找该目录下所有文件的提交
git log --since="1 month ago" -- [目录路径] --pretty=format:"%h|%an|%ae|%ad|%s"
```

### 步骤4: 统计提交者信息

收集所有相关提交的开发者信息：

**统计维度**：
- 开发者姓名
- 开发者邮箱
- 提交次数
- 最近提交时间
- 提交的文件列表

**统计规则**：
- 精确匹配的文件/行号：权重最高（权重3）
- 模糊匹配的类名/方法名：权重中等（权重2）
- 模块级别的提交：权重最低（权重1）

**输出格式**：
```
提交者统计:

  开发者A (邮箱@example.com):
    - 总分: [权重总和]
    - 精确匹配: [次数]次
    - 模糊匹配: [次数]次
    - 模块匹配: [次数]次
    - 最近提交: [日期]

  开发者B (邮箱@example.com):
    ...
```

### 步骤5: 确定责任开发者

根据统计结果确定最佳分配对象：

**分配规则**：
1. 优先选择权重最高的开发者
2. 如果权重相同，选择最近提交的开发者
3. 如果多人权重相同且最近提交时间相近，列出所有候选人让用户选择

**输出格式**：
```
推荐分配给: [开发者姓名] ([邮箱])

理由:
  - 最近1个月内提交[X]次相关代码
  - 修改了[文件路径]的[Y]处
  - 精确匹配权重: [X]
  - 总权重: [X]

其他候选人:
  - [开发者A]: 权重[X], 最近提交[日期]
  - [开发者B]: 权重[X], 最近提交[日期]
```

### 步骤6: 生成分析报告

完整输出分析结果供用户参考：

```
=== Bugly 责任分析报告 ===

堆栈信息:
  异常位置: [文件路径]:[行号]
  类/方法: [类名].[方法名]
  模块: [模块名]

Git提交分析:
  查找时间范围: [起始日期] - [结束日期] ([X]个月)
  匹配提交数: [X]次
  涉及开发者: [X]人

推荐分配:
  开发者: [姓名] ([邮箱])
  理由: [理由说明]

相关提交记录:
  1. [commit hash] - [日期] - [姓名]
     [提交信息]

  2. [commit hash] - [日期] - [姓名]
     [提交信息]
```

## 使用示例

### 示例1: 上传异常堆栈图片

用户上传一张包含以下堆栈的图片：

```
Thread 0 Crashed:
0  MyApp                     0x100123456 MyViewController.viewDidLoad() + 256 (MyViewController.swift:45)
1  MyApp                     0x100123789 MyViewController.setupUI() + 128 (MyViewController.swift:78)
...
```

**分析过程**：
1. 识别异常位置：`MyViewController.swift:45`，类名：`MyViewController`
2. 查找最近1个月修改过`MyViewController.swift`的提交
3. 搜索代码中包含`MyViewController`的提交
4. 统计各开发者的提交次数和权重
5. 推荐最合适的开发者

### 示例2: 提供堆栈文本

用户直接粘贴堆栈文本，skill直接分析并输出推荐结果。

## 重要提示

1. **时间范围**: 严格按照"1个月->2个月->3个月..."的规则回溯，确保找到最近活跃的开发者
2. **权重计算**: 精确匹配优先，避免将问题分配给只做了间接修改的开发者
3. **多候选人情况**: 当有多个开发者权重相近时，列出候选人让用户最终决定
4. **历史记录**: 展示相关的git提交记录，帮助用户理解推荐理由
5. **Git仓库**: 确保在正确的git仓库目录下执行git命令
6. **全类型适用**: 本技能对 Crash、ANR、FOOM 三种堆栈均适用，核心逻辑一致
