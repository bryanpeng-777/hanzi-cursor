# CO-STAR Prompt 生成器

用 CO-STAR 框架把模糊的任务描述变成结构严谨、效果稳定的系统提示词。

---

## 框架说明

CO-STAR 是单次任务/简单 Agent 的系统提示词写作框架，六个维度缺一不可：

| 维度 | 全称 | 作用 | 重要度 |
|------|------|------|--------|
| **C** | Context（背景） | 交代你是谁，在处理什么任务，让模型建立正确的世界观 | ⭐⭐⭐⭐ |
| **O** | Objective（目标） | 终点是什么，DoOD（Definition of Done）是什么 | ⭐⭐⭐⭐⭐ |
| **S** | Style（风格） | 是简洁的 RFC 文档还是严肃的代码审查，影响表达方式 | ⭐⭐⭐ |
| **T** | Tone（语气） | 正式/轻松/专业，决定整体氛围 | ⭐⭐ |
| **A** | Audience（受众） | 给谁看的，决定了深度和术语密度（小白 vs 架构师） | ⭐⭐⭐⭐ |
| **R** | Response（输出格式） | **最关键！** 规定输出格式（JSON / Markdown / 固定模板），决定下游能否解析 | ⭐⭐⭐⭐⭐ |

> **注**：如果是长期运行的复杂 Agent（如告警处理机器人），推荐用五层分层架构而非 CO-STAR。

## 工作流程

### Step 1：收集任务信息

从用户输入中提取任务描述。根据信息完整度选择模式：

**模式 A（快速模式）**：用户已提供足够信息（任务场景清晰、知道输出要什么），AI 直接推断六维内容，生成后告知推断依据。

**模式 B（引导模式）**：任务描述简短或模糊，AI 逐维追问：

```
收到！帮你用 CO-STAR 框架生成系统提示词。

先确认几个关键问题：

❓ C - 背景：这个 Prompt 用在什么场景/工具里？（如：Knot 定时任务 / Cursor Agent / 单次对话）
❓ O - 目标：AI 最终要产出什么？完成的标准是什么？
❓ R - 输出格式：希望 AI 输出什么格式？（Markdown 报告 / JSON / 固定模板 / 纯文本）
❓ A - 受众：产出给谁看？（开发者 / 测试同学 / 业务 PM / 自动化系统）

Style 和 Tone 我会根据受众和场景自动推断，无需特别说明。
（说「快点」可跳过追问，我来推断）
```

收到回答后，进入 Step 2。

### Step 2：生成结构化 System Prompt

基于六维信息，按以下模板生成 System Prompt：

```
## 角色与背景（Context）
你是 {角色描述}，运行在 {场景/平台}。
{1-3 句话描述任务背景和你拥有的能力/工具}

## 任务目标（Objective）
每次运行时，你需要完成：
{有序列表，列出 3-5 个具体步骤，每步 = 一个可验证的子动作}

完成标准（DoOD）：
{清晰描述什么叫"做完了"——如"输出完整报告且无 [ERROR] 标记"}

## 受众与深度（Audience）
{写给谁看，决定术语深度和解释粒度}
- 如果受众是{受众A}：{具体要求，如"使用专业术语无需解释"}
- 如果受众是{受众B}：{具体要求，如"附加名词解释"}

## 输出格式（Response）⭐ 最关键
输出必须严格遵循以下格式：

{在此提供完整的输出模板，含占位符、emoji 或表格。例如：}

---
📊 **{标题}**
时间：{时间范围}

**{分类1}**
{内容}

**{分类2}**
{内容}

**结论**：{结论}
---

不得输出模板之外的多余内容（如"好的，我来分析一下..."）。

## 风格与语气（Style / Tone）
- 风格：{简洁/详细/列表式/叙述式}
- 语气：{专业/轻松/严肃/中性}
- 禁止：{列出不希望出现的表达，如"不要废话开场白""不要解释你自己在做什么"}

## 异常处理
- 如果数据获取失败：输出 `[ERROR] {具体原因}，跳过本次执行`
- 如果返回结果为空：输出 `[空数据] 本次查询无结果，可能原因：{列举 2-3 个可能原因}`
- 不得编造任何数据，所有内容必须来自真实返回结果
```

### Step 3：输出与迭代

生成完成后，以 markdown 代码块呈现：

```
以下是用 CO-STAR 框架生成的 System Prompt，可直接粘贴使用：

---
{完整 System Prompt}
---

**生成依据：**
- C（背景）：{推断来源}
- O（目标）：{推断来源}
- S/T（风格语气）：{推断来源，如"根据受众为开发者，推断为专业简洁"}
- A（受众）：{推断来源}
- R（输出格式）：{推断来源}

如需调整，请告诉我（如：修改输出格式 / 调整语气 / 增加约束条件）。
```

每轮修改后，输出**完整**的最新版本，不输出 diff 片段。

## 注意事项

- **CO-STAR 适合场景**：单次任务、简单 Agent、Knot 定时推送、固定 Pipeline
- **不适合场景**：长期运行的复杂 Agent（改用五层分层架构，技能路径：`~/.claude/skills/five-layer-prompt-generator/`）
- **R 维度是灵魂**：输出格式定义越精确，AI 行为越稳定；模板中务必包含完整占位符
- **S/T 非核心**：技术场景下，Style/Tone 可由 Audience 推断，无需过度设计
- **生成后必须验证**：将生成的 Prompt 实际使用一次，观察是否符合预期，再反馈调整
