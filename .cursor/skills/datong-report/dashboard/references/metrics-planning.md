# 指标分类体系和规划规则

> 本文档在 Step 2 中使用，帮助根据项目分析结果规划指标。

> 🔀 **【前置】检查业务自定义指标规范（custom-specs/）**  
> 使用本文档前，先执行 `custom-specs/` 前置检查（详见 [../../references/custom-specs.md](../../references/custom-specs.md)）：  
> 1. 扫描 skill 根目录下 `custom-specs/` 是否存在与**指标规范**相关的 md（文件名含 `metric`/`indicator`/`kpi`/`okr`/`northstar`）  
> 2. 若命中 `## 覆盖` → 整段替换本文档对应分类体系/规划规则；若命中 `## 补充` → 与本文档默认规则**合并使用**  
> 3. 自定义规范与默认分类体系（通用指标 / 个性化指标 / North Star / 核心 / 诊断 / 护栏）的合并策略：  
>    - 自定义声明"必选指标" → 追加到清单，不因默认分类限制而过滤  
>    - 自定义声明"禁用指标或禁用分类"（如"不推荐 PV/UV 类"） → 从默认清单剔除  
>    - 自定义声明"自定义分类体系"（如替换"北极星/核心/诊断/护栏"为公司 OKR 分级） → 整体采纳  
>    - 自定义未涉及的分类项 → 按本文档默认规则兜底  
> 4. 目录不存在或无命中 → 完全按本文档默认规则执行  
> 5. 冲突硬性约束（事件名语义等） → 拒绝覆盖，在最终指标清单「规范来源」块中标注

## 事件名称规范

在规划指标前，必须明确大同标准事件名称：

| 事件名 | 含义 | 采集方式 | 关键参数 |
|--------|------|---------|---------|
| `dt_pgin` | 页面曝光（页面进入） | 声明式（SDK 自动采集） | `dt_pgid` |
| `dt_pgout` | 页面结束曝光（页面退出） | 声明式（SDK 自动采集） | `dt_pgid`, `dt_lvtm`（停留时长，毫秒） |
| `dt_imp` | 元素曝光 | 声明式（SDK 自动采集） | `dt_eid` |
| `dt_imp_end` | 元素结束曝光 | 声明式（SDK 自动采集） | `dt_eid` |
| `dt_clck` | 元素点击 | 声明式（SDK 自动采集） | `dt_eid` |
| 自定义事件 | 业务自定义行为（如 `form_submit`） | 代码打点（手动上报） | 业务自定义参数 |

---

## 埋点方式说明

| 埋点方式 | 含义 | 适用事件 | 实现方式 |
|---------|------|---------|---------|
| **声明式** | 在 DOM 元素上标记属性，采集 SDK 自动检测并上报 | `dt_pgin`、`dt_pgout`、`dt_imp`、`dt_imp_end`、`dt_clck` | 添加 `dt-pgid`、`dt-eid` 等 HTML 属性 |
| **代码打点** | 在业务代码中手动调用 SDK 上报方法 | 所有自定义行为事件 | 在对应代码位置调用 `sdk.report(eventName, params)` |

**判定原则**：
- 指标依赖的事件如果是页面曝光、元素曝光、元素点击 → **声明式**
- 指标依赖的事件需要在特定业务逻辑触发时上报 → **代码打点**

## 指标分类体系

### 一、通用指标（所有 Web 项目都适用）

无论项目性质如何，以下指标都建议纳入看板：

#### 流量指标

| 指标名称 | 计算方式 | 依赖事件 | 依赖参数 | 埋点方式 |
|---------|---------|---------|---------|:-------:|
| 页面 PV | COUNT(dt_pgin) | `dt_pgin` | `dt_pgid` | 声明式 |
| 页面 UV | COUNT(DISTINCT user_id) WHERE event=dt_pgin | `dt_pgin` | `dt_pgid` | 声明式 |
| 人均页面访问数 | PV / UV | `dt_pgin` | `dt_pgid` | 声明式 |
| 平均停留时长 | AVG(dt_lvtm) WHERE event=dt_pgout | `dt_pgout` | `dt_pgid`, `dt_lvtm` | 声明式 |

#### 互动指标

| 指标名称 | 计算方式 | 依赖事件 | 依赖参数 | 埋点方式 |
|---------|---------|---------|---------|:-------:|
| 元素点击次数 | COUNT(dt_clck) | `dt_clck` | `dt_eid` | 声明式 |
| 元素点击率（CTR） | COUNT(dt_clck) / COUNT(dt_imp) | `dt_clck` + `dt_imp` | `dt_eid` | 声明式 |
| 元素曝光次数 | COUNT(dt_imp) | `dt_imp` | `dt_eid` | 声明式 |

#### 转化漏斗指标

| 指标名称 | 计算方式 | 依赖事件 | 依赖参数 | 埋点方式 |
|---------|---------|---------|---------|:-------:|
| 漏斗转化率 | 下一步 UV / 上一步 UV | 各步骤对应事件 | 各步骤标识 | 视步骤而定 |
| 整体转化率 | 最终步骤 UV / 首步骤 UV | 首末步骤事件 | — | 视步骤而定 |

### 二、个性化指标（根据项目性质推荐）

**不预设固定的业务场景模板**，而是根据 Step 1.2 的项目分析结果，结合以下维度动态推荐：

#### 推荐策略

| 项目分析发现 | 推荐的个性化指标方向 | 典型事件 | 埋点方式 |
|-------------|-------------------|---------|:-------:|
| 有表单/输入组件 | 表单提交率、字段填写完成率 | 自定义事件（如 `form_submit`） | 代码打点 |
| 有搜索功能 | 搜索使用率、搜索结果点击率 | 自定义事件（如 `search_query`） | 代码打点 |
| 有列表/信息流 | 列表项曝光率、列表项点击率 | `dt_imp` + `dt_clck` | 声明式 |
| 有弹窗/模态框 | 弹窗触发率、弹窗关闭率 | `dt_imp` + `dt_clck` 或自定义事件 | 视情况而定 |
| 有文件上传/下载 | 上传成功率、下载次数 | 自定义事件 | 代码打点 |
| 有多步骤流程（向导） | 各步骤转化率、完成率 | 自定义事件 | 代码打点 |
| 有 Tab/导航切换 | 各 Tab 使用分布、切换频率 | `dt_clck` | 声明式 |
| 有视频/音频播放 | 播放率、播放完成率 | 自定义事件 | 代码打点 |
| 有登录/注册 | 登录转化率、注册完成率 | 自定义事件 | 代码打点 |
| 有购物车/订单 | 加购率、下单转化率、客单价 | 自定义事件 | 代码打点 |
| 有评论/点赞/分享 | 互动率、人均互动次数 | 自定义事件或 `dt_clck` | 视情况而定 |
| 有图表/数据展示 | 图表查看率、筛选使用率 | `dt_imp` + `dt_clck` 或自定义事件 | 视情况而定 |

**"视情况而定"判定规则**：
- 如果交互本身就是一次点击或元素曝光 → 声明式
- 如果需要捕获业务状态变化（如请求成功/失败）→ 代码打点

> ⚠️ 不要生搬硬套上表。应结合实际代码分析，只推荐项目中**确实存在**对应功能的指标。

### 三、场景指标（基于业务场景库推荐）

当 Step 1.5 成功匹配到业务场景时，场景库提供**垂直行业级的指标推荐**，每个指标自带完整的口径定义和所需埋点。

> 📖 场景库文件位于 `scenario-library/` 目录，使用总则见 `scenario-library/00-usage-guide.md`

#### 场景库覆盖范围

| 场景 | 典型 North Star | 文件 |
|------|---------------|------|
| 通用产品增长 | 每周完成关键价值动作的活跃用户数 | `scenario-library/02-generic-product-growth.md` |
| 电商与零售 | 周支付买家数 | `scenario-library/03-ecommerce-retail.md` |
| 内容社区与媒体 | 每周完成高质量内容消费的用户数 | `scenario-library/04-content-community-media.md` |
| SaaS 与订阅 / B2B | 每周完成核心工作流的活跃账号数 | `scenario-library/05-saas-subscription-b2b.md` |
| 市场投放与增长营销 | 高质量转化数 | `scenario-library/06-marketing-acquisition.md` |
| 销售线索与 CRM | 赢单收入/成交金额 | `scenario-library/07-sales-crm.md` |
| 教育与学习产品 | 课程完成人数/完成率 | `scenario-library/08-education-learning.md` |
| 游戏与 LiveOps | D7/D30 retained players | `scenario-library/09-gaming-liveops.md` |
| 金融理财与支付 | 月活跃交易用户数 | `scenario-library/10-fintech-payments.md` |
| 客服与服务运营 | SLA 内解决率 | `scenario-library/11-support-service-ops.md` |

#### 场景指标的使用规则

1. **每个推荐指标必须写出以下字段**：类型（North Star / 核心结果 / 诊断 / 护栏）、何时推荐、建议口径、需要的埋点/数据、关键属性/常见切片
2. **事件命名映射**：场景库使用业务语义事件名（如 `order_pay_success`），落地到大同时映射为 `dt_` 标准事件或自定义事件
3. **推荐上限**：1 North Star + 5～8 核心结果 + 3～6 诊断 + 2～4 护栏
4. **禁止乱推的通用规则**：
   - 没有订单/支付，不推 GMV
   - 没有订阅/账单，不推 MRR/NRR
   - 没有工单状态流转，不推 FRT/解决时长
   - 没有 cohort 起点或时间窗，不要装作已经定义了留存、复购、LTV
   - 没有稳定 user_id，不要轻易推荐跨天/跨周期指标

> ⚠️ 场景指标是经验参考，不是硬性要求。如果仓库证据不足，宁可不推也不要凑数。

## 指标规划流程

### 1. 基于项目分析确定指标集

```
Step 1.2 的项目分析摘要 + Step 1.5 的场景识别结果
    │
    ├─ 所有项目 → 纳入「通用指标」（流量 + 互动 + 漏斗基础）
    │
    ├─ 匹配到场景 → 以「场景指标」为核心基线，补充通用指标
    │
    └─ 未匹配场景 → 根据发现的功能特征，从「个性化指标」表中匹配推荐
```

### 2. 筛选核心指标

不要一次性给太多指标。优先选择：

- **北极星指标**（1 个）：最能反映业务健康度的关键指标
- **核心指标**（3-5 个）：日常关注的关键数据
- **辅助指标**（若干）：帮助分析问题的补充数据

### 3. 推导埋点依赖并确定埋点方式

每个指标都需要明确：

| 需要确认的信息 | 说明 |
|-------------|------|
| 依赖哪些事件 | 计算该指标需要哪些埋点事件的数据 |
| 依赖哪些参数 | 事件中需要携带哪些字段 |
| 埋点方式 | 声明式 or 代码打点（按上文判定规则） |
| 计算维度 | 按什么维度拆分（页面、时间、用户群等） |
| 计算周期 | 日/周/月/实时 |

### 4. 输出指标清单

格式见 SKILL.md 中 Step 2.3 的指标清单表，**必须包含「埋点方式」列**。
