# 技能发现与自动化模块

当 Agent 规划出 [人工] 步骤时，主动搜索是否有现成的 Skill 或 MCP 能将该步骤自动化。目标是让 Agent 的能力边界随使用不断扩展。

---

## 触发条件

在 Step 3 规划执行步骤时，对每个标记为 **[人工]** 的步骤进行自动化可行性评估。

### 可自动化的 [人工] 步骤（值得搜索）

- 编译、构建、打包
- 运行测试、检查日志
- 发布、部署操作
- 数据查询、报表生成
- 文档格式转换
- 浏览器操作、UI 自动化测试
- 消息通知、定时任务

### 不可自动化的 [人工] 步骤（跳过搜索）

- 找人沟通、对齐需求
- 主观判断、设计评审
- 物理操作（如连接设备）
- 需要账号权限且无法代理的操作

---

## 搜索源（按优先级）

### 第一层：已有资源（最快）

| 搜索源 | 方法 | 说明 |
|--------|------|------|
| **已安装的 Skills** | 扫描 `available_skills` 列表 | 可能有技能之前没匹配到但某个步骤可以用 |
| **已安装的 MCP 工具** | 浏览 mcps/ 目录下各 server 的 tools/ | 如 lego-mcp 有 devops_start_pipeline 可用于编译 |

### 第二层：技能市场（中等速度）

| 搜索源 | 方法 | 说明 |
|--------|------|------|
| **search-skill** | 读取并调用 `skill-from-masters/skills/search-skill/SKILL.md` | 从 anthropics/skills、ComposioHQ、skills.sh、skillsmp.com 搜索 |
| **skills.sh** | `WebFetch("https://skills.sh")` 搜索 | Vercel 官方 Skill 目录 |
| **skillhub** | 搜索 skillhub 平台 | 外部技能聚合平台 |

### 第三层：MCP 生态（需安装）

| 搜索源 | 方法 | 说明 |
|--------|------|------|
| **mcp.so** | `WebFetch("https://mcp.so")` 搜索 | MCP 服务器目录，按类别检索 |
| **glama.ai/mcp** | `WebFetch("https://glama.ai/mcp")` 搜索 | MCP 聚合平台，支持搜索 |
| **smithery.ai** | `WebFetch("https://smithery.ai")` 搜索 | MCP 服务器注册中心 |
| **npm** | `WebSearch("mcp server <关键词> npm")` | 很多 MCP 以 npm 包发布 |

### 第四层：通用搜索（最广）

| 搜索源 | 方法 | 说明 |
|--------|------|------|
| **GitHub** | `WebSearch("claude code skill <关键词> github")` | 开源社区 |
| **Web** | `WebSearch("<关键词> automation tool CLI")` | 可能有 CLI 工具或脚本可用 |

## 搜索流程

### 1. 评估 & 提出建议

对每个 [人工] 步骤评估自动化可行性，汇总后展示给用户：

```
🔍 发现以下 [人工] 步骤可能可以自动化：

  步骤 5 [人工] 编译并运行验证
    → 可能有编译自动化的 Skill 或 MCP

  步骤 7 [人工] 提交代码
    → 已有 git-commit 技能可以处理（已安装）

  步骤 3 [人工] 找 XX 同学对齐
    → 跳过（需要人际沟通，无法自动化）

需要我帮你搜索可用的自动化工具吗？
```

### 2. 用户确认后搜索

按优先级从第一层到第四层逐层搜索，找到候选后立即展示，不必搜完所有层：

```
🔎 搜索结果：

步骤 5 [人工] 编译并运行验证：
  ① [已安装 MCP] lego-mcp → devops_start_pipeline 工具
     可以触发远程编译流水线，无需本地 Xcode
  ② [Skill 市场] xcode-build-skill (skills.sh)
     Stars: 230 | 自动化 Xcode 编译和测试
  ③ [MCP] xcode-mcp (mcp.so)
     可以读取 Xcode 日志、触发编译

要试哪个？说序号我来安装和测试。
```

### 3. 安装 & 测试

用户选择后：

1. **安装**：
   - Skill → 下载 SKILL.md 到 `~/.claude/skills/` 或 `~/.cursor/skills-cursor/`
   - MCP → 按说明配置到对应的 MCP 配置文件中

2. **测试**：用当前任务的实际场景做一次测试调用
   - 成功 → 记录这个工具可用，更新执行计划，将 [人工] 改为 [AI]
   - 失败 → 告知用户原因，卸载/删除，保持 [人工]

```
🧪 测试 xcode-mcp：

安装完成，尝试触发一次编译...
✅ 编译成功！耗时 45s，输出日志正常。

步骤 5 已更新：[人工] → [AI]（使用 xcode-mcp 自动编译）
```

或

```
🧪 测试 xcode-mcp：

安装完成，尝试触发一次编译...
❌ 失败：需要 Xcode 命令行工具路径配置，当前环境不支持

已卸载 xcode-mcp，步骤 5 保持 [人工]。
```

### 4. 无现成工具时：评估自建 Skill

如果四层搜索都没有找到合适的工具，评估是否值得为这类步骤自建一个 Skill：

**值得自建的信号**：
- 这个步骤在多条任务中会反复出现（如「检查某类日志」「生成某类报告」）
- 步骤逻辑可以标准化为固定流程
- 自建后长期收益大于一次性人工操作

**不值得自建的信号**：
- 一次性任务，以后不太会再遇到
- 步骤过于依赖特定上下文，难以通用化
- 自建成本远高于手动操作

评估后向用户展示建议：

```
🏗️ 未找到现成工具，但这个步骤可能值得自建一个 Skill：

  步骤 5 [人工] 编译并运行验证
  
  建议理由：编译验证在几乎每个代码修改任务中都会出现，
  自建一个 Skill 封装 xcodebuild 命令 + 日志解析，后续所有任务都能复用。

  预计自建方式：调用 skill-creator 技能创建

是否现在创建这个 Skill？
  - 说「建」→ 调用 skill-creator 创建并测试
  - 说「不用」→ 保持 [人工]，继续当前任务
```

用户确认「建」后，调用 `skill-creator` 技能创建新 Skill，创建完成后用当前任务实测，可用则更新计划。

### 5. 沉淀发现

无论成功还是失败，将发现结果沉淀到知识库（通过 knowledge-collector），以便下次遇到类似步骤时直接复用：

- 找到现成工具：记录「XX 步骤可以用 XX 工具自动化」
- 自建 Skill：记录「为 XX 场景自建了 XX 技能」
- 搜索无果：记录「XX 场景目前无自动化方案，原因是...」

---

## 注意事项

- **不要阻塞主流程**：搜索是可选的优化环节，用户说「不搜了」「直接继续」时立即跳过
- **安全第一**：安装前检查 Skill/MCP 的安全性（参考 search-skill 的安全检查标准）
- **优先已有资源**：很多时候已安装的 MCP 就有对应工具，只是之前没用过
- **记录结果**：每次搜索的成功/失败结果都值得沉淀，让 Agent 越来越聪明
