# 任务执行模块

Agent 按照用户确认的执行计划，逐步推进任务。本模块定义执行规则、输出格式和异常处理机制。

---

## 🚫 STOP：执行第一步之前必须先完成「3 轮复查」

> 🔴 **进入 Step 4 后，读取本文件的第一件事不是执行，而是完成下方「检查任务计划（执行前 3 轮复查）」并输出复查结论。复查结论未输出 = 未完成，不得执行任何步骤。**
>
> ⚠️ 常见错误：读完本文件后直接开始执行步骤 1，跳过复查。这是明确禁止的行为。

---

## 执行规则

1. **[AI] 步骤**：直接执行，完成后输出结果，自动进入下一步
2. **[AI建议] 步骤**：输出思考和建议，等待用户做出选择后继续
3. **[人工] 步骤**：输出操作说明，然后等待。用户说「这一步完成了」「done」「搞定了」「好了」「完成」等类似表述时，才继续下一步

当 Step 3 只定了**若干助手**时，**一步**通常等于 **一次** 某助手的 `Task`；**不要** 在父层把该助手内部子技能再拆成多步自跑。

---

## ⚠️ 铁律：有小助手必须通过 `Task` 执行；父层不执行子技能

**Step 3 编排层已改为只写「哪个助手负什么责」，不再预写「助手 → 子技能」。** 执行时以 **Step3令牌 + 协作方案中的助手列表** 为准：每出现一位需执行的小助手 → **一次** `Read(agent.md)` + **一次** `Task(generalPurpose, 注入全文)`；**禁止** 在父上下文 `Read` 该助手的子技能 `SKILL.md` 并自跑。

### 判断方式（执行时）

查看 Step3令牌与 Step 3 确认稿：

- 含 `[某助手名]` 且该步是**跑该助手**（全责/分块责任）→ **必须** `Task` 进该助手，**不** 在父层根据子技能名抢跑
- 令牌为 `[3.1] 子上下文:<技能名>` 且**无**对应助手 → **仅** 在子上下文中读该 `SKILL.md` 跑通，**父会话不读不跑**
- 纯 `[人工]` 节点 → 按说明等人，不读技能

### 执行方式

| 情况 | 执行方式 |
|------|---------|
| **小助手（任意子技能归属其下）** | `Read ~/.claude/agents/<助手>.md` → `Task(generalPurpose, …)`；**子技能只由 subagent 内部 Read** |
| **无助手、令牌注明子上下文独立技能** | **仅** 在子上下文中读 `SKILL.md` 并执行，**父层不读** |

### 有小助手时的执行流程（Cursor 强制规范）

> 🔴 **所有小助手均为 subagent，Cursor 中必须且只能通过 `Task(subagent_type="generalPurpose")` 启动，无任何例外。**

```
Step 1: Read("~/.claude/agents/<助手名>.md")   ← 读取 agent 文件全文，用于注入 prompt
Step 2: Task(
  subagent_type="generalPurpose",              ← 固定，不写助手名
  prompt="你现在扮演 <助手名>...\n\n<agent文件全文>\n\n【当前任务】..."
)
```

**三条铁律（违反任何一条都是错误执行）**：
- 🔴 `subagent_type` **永远写 `"generalPurpose"`**，不写助手名
- 🔴 agent 文件全文**必须完整注入** prompt，不能只写助手名
- 🔴 每个助手**独立一次 Task 调用**，不在同一 prompt 里合并多个助手

---

### ⛔ 执行阶段绝对禁止的操作

| ❌ 禁止 | 原因 |
|--------|------|
| `Read ~/.claude/skills/<子技能名>/SKILL.md`（当该技能有归属助手时） | 读了就会触发「自己执行」冲动，直接绕过 subagent |
| 在父上下文中直接运行子技能里的脚本/命令 | 即使脚本只有一行，也属于绕过小助手 |
| `Read ~/.claude/agents/<助手名>.md` 后不调用 Task 直接执行 | 读了 agent 文件的唯一合法后续是 Task() |

> ❌ **错误做法**：执行时因「知道会用到某子技能」就先在父层 `Read ~/.claude/skills/.../SKILL.md` 并自跑
>
> ✅ **正确做法**：`Read ~/.claude/agents/bugly-assistant.md` → `Task(...)`，子技能**仅**在 subagent 内读取

**此规则无任何例外。即使只涉及一个「子技能」，也必须通过 `Task` 进助手（或子上下文），父上下文不读子技能。**

## 检查任务计划（执行前 3 轮复查，Step 4 第一步执行前强制触发）

> 🔴 **读取到 Step3令牌、即将执行第一个步骤时，须完成 3 轮复查。与规划阶段同构：第 1 轮重点为「父层是否又偷塞了技能/细案」。**

此复查与 `task-planning.md` 中 3 轮一致；若执行前发现父层计划又出现技能跑单，**先回 Step 3 删净** 再写令牌。

### 第 1 轮复查：防父层执行诱惑

- 将执行的「下一步」若写成了具体技能/路径/行号在**用户可见计划**里 → 视为违规，**不得**据此刻开始执行；应回到 Step 3。
- 令牌与 Step3 成稿仅含 **助手责任** 的 → ✅，下一步只能是 **Task(助手)**。

### 第 2 轮复查：总管安排 / 执行顺序

- 多助手时是否按**依赖**先后 `Task`？并行列是否仍独立？

### 第 3 轮复查：遗漏助手

- 与规划阶段同：缺助手轨则补 **助手+责任** 名，不补子技能名。

---

### 复查输出格式

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔎 执行前计划复查（3 轮）
  第 1 轮 技能归属：✅ 全部正确
  第 2 轮 总管安排：✅ 顺序与上下文模式无误
  第 3 轮 遗漏助手：✅ 无遗漏
复查通过，开始执行 →
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**→ 3 轮全部通过后，才开始执行计划第一步。**

## iOS 代码修改验证规范

**所有涉及 iOS 代码修改的任务，执行步骤中必须包含验证环节**，流程如下：

1. **[AI]** 在关键逻辑处添加验证日志，使用 `WEGLogBizManager commonLog`，`messageName` 加 `verify_` 前缀：
   ```objc
   [[WEGLogBizManager sharedManager] commonLog:OTLogLevelInfo
                                   messageName:@"verify_xxx_action"
                                    moduleName:@"YourManager"
                                          type:OTCommonLogTypeBefore
                                    attributes:@{@"key": @"value"}];
   ```
2. **[人工]** 编译运行 App，触发相关功能
3. **[AI]** 在 `/Users/bryanpeng/work_tree_bugfix/aiworkspace/log` 中搜索 `verify_` 日志，验证逻辑正确性
4. **[AI]** 验证通过后删除所有验证日志，恢复代码干净状态

**注意**：
- `NSLog` 只在 Xcode Debug Console 可见，AI 无法读取，**禁止用于验证日志**
- Xcode MCP 只能编译（`BuildProject`），无法读取运行时控制台
- 验证日志在正式提交前必须全部删除

## 步骤执行输出

每执行一步，**先输出路由核查行**（涉及技能调用时必填），再输出进度：

```

📌 步骤 3/7 [AI建议] 设计修改方案
📂 执行路径：[独立技能] Read ~/.claude/skills/xxx/SKILL.md
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**路由核查行填写规则**（涉及助手或子上下文的**每一步**都输出；**编排层不预写子技能**，核查行**不带** 子技能名）：

| 本步在干什么 | 路由核查行 |
|-------------|-----------|
| 跑 `bugly-assistant` 对应责任块 | `📂 执行路径：[助手] Read ~/.claude/agents/bugly-assistant.md → Task(generalPurpose)` |
| 跑 `dev-assistant` 全包 | `📂 执行路径：[助手] Read ~/.claude/agents/dev-assistant.md → Task(generalPurpose)` |

| `[人工]` | `📂 执行路径：[人工] 无 Task` |

> ⚠️ 路由核查行出现 `~/.claude/agents/` 路径时，**下一个动作必须是 Task()，没有其他选项**。

## 异常处理与中途调整

执行过程中可能出现各种情况，需要灵活应对：

### AI 步骤失败

输出失败原因和已尝试的方法，提供选项：

```
⚠️ 步骤 2 执行异常：未能在代码库中找到相关模块
已尝试：搜索了 flutter_module 和 social-ios 两个项目
可能原因：模块名称与任务描述不一致

你希望：
A) 补充更多信息让我重试
B) 跳过这步，直接进入下一步
C) 改为你手动定位，告诉我路径
```

### 人工步骤反馈问题

用户说「这步有问题」「失败了」「报错了」→ 询问具体情况，根据情况决定回退、重做还是调整计划

### 中途调整计划

- 用户说「加一步」「这步不需要了」「先做后面的」→ 动态修改执行计划并展示更新后的计划
- 用户说「回到步骤 N」「重做上一步」→ 回退到指定步骤

### 放弃当前任务

- 用户说「放弃这个任务」「不做了」「skip this task」→ 确认后跳过，不打勾，直接进入下一条任务的选取
- 放弃的任务保持 `[ ]` 未完成状态，下次开工仍会被选中
