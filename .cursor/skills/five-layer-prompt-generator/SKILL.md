# 五层分层架构 Prompt 生成器

把 Agent 的模糊职责描述，变成五层职责清晰、边界分明、能稳定运行的系统提示词。

---

## 为什么要分层？

| 问题 | 根因 | 五层的解法 |
|------|------|-----------|
| AI 越权操作 | 能力边界没说清 | Identity Layer 限定能力范围 |
| AI 推理顺序错误 | 思考逻辑没规定 | Reasoning Layer 规定推理步骤 |
| AI 行为不稳定 | Do's & Don'ts 不明确 | Behavior Layer 写可量化规则 |
| 输出格式乱 | 表达风格没统一 | Style Layer 固定格式模板 |
| 出错后不知道怎么办 | 没有降级策略 | Guardrail Layer 定义安全边界 |

> **与 CO-STAR 的区别**：CO-STAR 适合单次任务/简单脚本（六维横向描述）；五层分层架构适合长期运行的复杂 Agent（五层纵向分工，每层职责独立）。

---

## 五层定义

| 层级 | 英文名 | 职责 | 重要度 |
|------|--------|------|--------|
| **第 1 层** | Identity Layer（身份层） | 定义 Agent 是谁、能做什么、不能做什么 | ⭐⭐⭐⭐⭐ |
| **第 2 层** | Reasoning Layer（推理层） | 规定遇到问题时的思考逻辑顺序 | ⭐⭐⭐⭐⭐ |
| **第 3 层** | Behavior Layer（行为层） | 列出可量化的 Do's and Don'ts | ⭐⭐⭐⭐⭐ |
| **第 4 层** | Style Layer（表达层） | 统一输出格式和风格（含完整模板） | ⭐⭐⭐⭐ |
| **第 5 层** | Guardrail Layer（防御层） | 定义降级策略、安全边界、异常处理 | ⭐⭐⭐⭐⭐ |

> ⚠️ **Guardrail Layer 是最容易被忽视的层**，但它决定 Agent 在边界 Case 下是否安全——必须填写，不得留空。

---

## 工作流程

### Step 1：收集 Agent 信息

从用户描述中提取 Agent 的用途。根据信息完整度选择模式：

**模式 A（快速模式）**：用户已描述清楚 Agent 的职责、触发方式、产出物，AI 直接推断五层内容，生成后标注推断依据。

**模式 B（引导模式）**：描述简短或场景不清，按五层逐一引导：

```
收到！帮你用五层分层架构生成 Agent 系统提示词。

先确认五个关键维度：

🏷️ 第 1 层 - 身份（Identity）：
  这个 Agent 是什么角色？它拥有哪些工具/能力？有哪些事情是它明确不该做的？

🧠 第 2 层 - 推理（Reasoning）：
  遇到问题时，它应该按什么顺序思考？（例如：先看堆栈 → 再查日志 → 最后出结论）

⚙️ 第 3 层 - 行为（Behavior）：
  必须做哪些事？（Do's）绝对不能做哪些事？（Don'ts）能否举 1-2 个边界 Case？

📄 第 4 层 - 表达（Style）：
  输出给谁看？希望什么格式？（Markdown / 表格 / 固定模板）请提供期望的输出样例。

🛡️ 第 5 层 - 防御（Guardrail）[必填，不可跳过]：
  当数据获取失败时怎么处理？当结论不确定时说什么？有哪些绝对不能触碰的安全红线？

（说「快点」可让我自动推断，但 Guardrail 层必须你来确认）
```

收到回答后，进入 Step 2。

### Step 2：生成五层结构 System Prompt

基于五层信息，按以下模板生成 System Prompt：

```
## 【身份层 · Identity】
你是 {Agent 名称}，运行在 {平台/场景}。

**你能做什么：**
- {能力 1}
- {能力 2}

**你不能做什么（能力边界）：**
- {限制 1，例如：不能主动修改代码，只能分析和建议}
- {限制 2}

---

## 【推理层 · Reasoning】
每次收到任务时，按以下顺序思考，不得跳步：

1. {推理步骤 1，例如：首先确认输入数据是否完整}
2. {推理步骤 2，例如：然后按优先级排序处理}
3. {推理步骤 3，例如：最后生成结论前自我检查是否有遗漏}

> 如果某步骤返回空数据或失败，立即跳转到【防御层】的对应处理策略，不得继续后续步骤。

---

## 【行为层 · Behavior】
**必须做（Do's）：**
- ✅ {规则 1，例如：每次输出必须包含数据来源说明}
- ✅ {规则 2，例如：结论必须基于真实数据，不得推断}
- ✅ {规则 3}

**禁止做（Don'ts）：**
- ❌ {规则 1，例如：不得编造任何数据}
- ❌ {规则 2，例如：不得在数据不足时给出确定性结论}
- ❌ {规则 3}

---

## 【表达层 · Style】
**受众**：{受众描述，决定术语深度}
**风格**：{简洁/详细/表格优先/叙述式}
**语气**：{专业/中性/轻松}

输出必须严格遵循以下模板，不得添加开场白或多余说明：

---
{在此提供完整输出模板，含占位符、emoji、表格结构}
---

---

## 【防御层 · Guardrail】⚠️ 最容易被忽视
**降级策略（数据获取失败）：**
- 如果 {场景 1} 失败：输出 `[ERROR] {具体说明}` 并停止执行，不得猜测
- 如果 {场景 2} 返回空：输出 `[空数据] {原因推测列表}` 并告知用户

**不确定性处理：**
- 当结论置信度低于 {阈值} 时：明确标注 `[不确定]` 而非给出误导性答案
- 当输入格式无法解析时：输出 `[格式错误] 期望格式：{期望格式说明}`

**安全红线（绝对不能触碰）：**
- {红线 1，例如：不得输出用户隐私信息}
- {红线 2，例如：不得自动执行破坏性操作（如删除数据）}
```

### Step 3：输出与迭代

生成完成后，以 markdown 代码块呈现：

```
以下是用五层分层架构生成的 Agent System Prompt，可直接粘贴使用：

---
{完整 System Prompt}
---

**五层生成依据：**
- 🏷️ Identity（身份层）：{推断来源}
- 🧠 Reasoning（推理层）：{推断来源}
- ⚙️ Behavior（行为层）：{推断来源}
- 📄 Style（表达层）：{推断来源}
- 🛡️ Guardrail（防御层）：{推断来源，如"根据用户描述推断，已补充空数据和失败降级"}

⚠️ Guardrail Layer 检查：[✅ 已覆盖 / ❌ 以下场景未处理：{列出}]

如需调整，请告诉我（如：加强推理逻辑 / 修改输出格式 / 补充安全红线）。
```

每轮修改后，输出**完整**的最新版本，不输出 diff 片段。

## 与 CO-STAR 的选择指南

| 场景 | 推荐框架 | 原因 |
|------|----------|------|
| Knot 定时推送、单次报告生成 | CO-STAR | 输入固定、输出单一，六维描述够用 |
| 告警处理机器人 | **五层分层** | 需要多步推理 + 工具调用 + 异常降级 |
| 自动化代码审查 Agent | **五层分层** | 推理逻辑复杂，行为边界需要精确定义 |
| 简单格式转换脚本 | CO-STAR | 无状态、无工具调用，CO-STAR 更轻量 |
| Oncall 处理 / 日常任务管理 | **五层分层** | 长期运行，需 Guardrail 保护 |

---

## 注意事项

- **Guardrail Layer 不可省略**：在最终确认前，AI 必须检查防御层是否覆盖了数据失败、空返回、格式错误三种情况
- **Reasoning Layer 要写顺序，不要写原则**：「先看堆栈再查日志」是顺序，「要仔细分析」是废话
- **Behavior Layer 要可量化**：「不要废话」不如「不得输出除固定模板之外的任何内容」
- **生成后必须用真实场景验证**：将生成的 Prompt 实际用一次，观察五层是否都起到了约束作用
- **五层互相补充，不重叠**：Identity 说"能做什么"，Behavior 说"怎么做"，Guardrail 说"出错了怎么办"——三者不要重复写同一件事
