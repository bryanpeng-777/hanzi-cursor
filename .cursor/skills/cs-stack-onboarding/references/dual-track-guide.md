# 双线并行开发最佳实践

基础建设线（infra）和产品业务线（product）分两条并行线开发时的操作指南。

## 日常开发分工

| 场景 | 建议 |
|-----|-----|
| **基础线日常维护** | 在基础线只修改框架文件（`lib/network/`、`lib/storage/`、`lib/utils/`、`main.dart` 初始化部分、`pubspec.yaml` 框架依赖）；不要在基础线开发业务功能 |
| **产品线日常开发** | 在 `lib/features/` 下开发业务，不改动框架文件；若需调整框架配置，先在基础线修改再合入 |

## 合并策略

| 场景 | 建议 |
|-----|-----|
| **合并时机** | 建议在基础线完成一个完整更新（如升级某个框架库版本）后再合入产品线；避免频繁合并半成品状态 |
| **合并后验证** | 合入后立即运行「合并后修复模式」，确认冲突解决和漂移修复；再执行 `flutter analyze` 验证 |
| **版本锚点共享** | 将 `.cs-stack.json` 提交到两条分支，这样合并时该文件的冲突本身就能揭示两条线的接入差异 |
