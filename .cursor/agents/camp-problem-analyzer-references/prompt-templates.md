```
- 问题描述：{problem_description}
- 发生时间：{time}

{如果五要素中包含「分析时间窗口」字段，追加：}
```

## Bugly 结论注入块（串行 Phase 2 追加）

在串行两阶段的 Phase 2 中，需将此块追加到标准模板后面：

```
## Bugly 分析结论（Phase 1 已完成，作为上下文直接使用）

精确崩溃/ANR 时间戳：{从 Bugly 结论中提取的精确时间戳}
堆栈摘要：{Bugly 堆栈摘要，若有}
Bugly Issue 链接：{链接，若有}

## Crash/ANR 精确时间点分析（优化方法，必须遵守）

本问题类型为 Crash/ANR，精确时间戳已由 Bugly 提供（见上方），**直接使用上方精确时间戳**，禁止自行查询 Bugly 或猜测时间，禁止拉取全天日志做累计统计，必须按以下步骤执行：

1. **以上方 Bugly 精确时间戳为基准，仅查询前后 5 分钟的伽利略日志**（替代全天查询）
2. **重点关注时间窗口内**：
   - FlutterEngineCreateToFirstFrameInit（start/end 成对，计算单次 Engine 初始化耗时）
   - FlutterContainerLifeCycle（孤悬的 start 无对应 end = 主线程阻塞点，ANR 专属）
   - FlutterViewErrorShow（触发 Engine 销毁的错误时刻）
   - NetRequest（接口失败与重试风暴的精确时序）
   - 崩溃前最后几条日志（定位 Crash 触发的业务上下文）
3. **按时间顺序还原单次触发链路**（目标：10~20 条日志完整还原）
4. **Engine 初始化次数口径**：日志条数 ÷ 2 = 实际次数（start+end 成对）
```

## FOOM 分析注入块（Step 5 伽利略 prompt 追加）

仅当问题描述含「FOOM」时，将此块追加到标准分析器 prompt 后面：

```
## FOOM 专项分析（必须遵守）

本问题类型为 FOOM（内存超限被系统强杀）。禁止按 Crash/ANR 精确时间点方式分析，必须按以下步骤执行：

1. **时间范围**：以 FOOM 发生时刻为终点，向前拉取 **30 分钟**的伽利略日志

2. **专项检查 A：页面多次打开检测**
   查询 `moduleName=FlutterContainerLifeCycle`，提取所有 `start` / `end` 事件，按页面名称分组统计：
   - 重点关注 start 次数 ≥ 3 次的页面
   - 计算 start - end 差值（差值 > 0 = 页面未被正常释放，是内存泄漏候选）
   - 输出表格：页面名 | start 次数 | end 次数 | 差值（未释放）| 是否可疑

3. **专项检查 B：用户操作路径分析**
   从 `FlutterContainerLifeCycle` start 事件 + `InnerRouter`/`OutRouter` 路由记录，按时间顺序还原完整导航链路：
   - 识别循环导航（A→B→A→B 往复）
   - 识别深栈累积（连续打开 ≥ 5 页未返回）
   - 识别短时间内（5 分钟内）重复进入同一功能的行为
   - 输出完整操作序列（时间戳 + 页面名），标注异常片段

4. **综合结论**：
   - 最可能导致内存堆积的操作序列
   - FOOM 前页面栈估算深度（未释放 start 总数）
   - 最可疑的内存泄漏页面/模块
```

```

## ⚠️ 第零步：平台归属确认（必须最先执行，不得跳过）

在做任何代码分析之前，先从以下证据中判断问题属于哪个平台：

**证据来源优先级**（按可信度从高到低）：

| 证据 | iOS 特征 | Android 特征 | Flutter 特征 |
|------|---------|-------------|-------------|
| xlog 包名 | `com.tencent.smoba` | `com.tencent.gamehelper.smoba` | — |
| pf 参数 | 含 `iphone`/`ios`/`m_qq_wallet` | 含 `android` | — |
| Bugly 堆栈语言 | ObjC/Swift 符号 | Java/Kotlin 符号 | Dart 符号（`dart:` 前缀） |
| 设备型号 | iPhone/iPad | 非苹果品牌 | — |
| 崩溃文件后缀 | `.m`/`.swift` | `.java`/`.kt` | `.dart` |

**平台 → 代码仓库映射**：

| 平台 | 可分析的代码位置 |
|------|----------------|
| **iOS** | `WEGGlue/`、`WEGLauncher/`、`CampCore/`、`WEGBase/`、`WEGFlutter/` 等 ObjC/Swift |
| **Flutter** | `flutter_module/lib/`（Dart，与 iOS/Android 共用） |
| **Android** | ⚠️ Android 营地代码**不在本 monorepo**，无法在此仓库中分析 |
| **游戏本身**（王者荣耀等） | ⚠️ 与营地 App 无关，属于游戏侧问题，不在本仓库 |

**必须输出平台确认卡片**（格式固定，不可省略）：

```
🔍 平台归属确认
  证据：{列举用到的具体证据，如「xlog 包名 com.tencent.gamehelper.smoba」「pf=wechat_wx-2001-android-sample」}
  平台结论：{iOS / Android / Flutter / 游戏 / 混合（如 Flutter + iOS）/ 不确定}
  分析范围：{将在哪些代码路径分析} 或 {声明：「Android 代码不在本 monorepo，本次无法进行代码分析，建议查看 Android 侧仓库」}
```

⛔ **若判断为 Android 或游戏问题**：输出平台确认卡片后**立即停止**，不得继续进行代码定位，直接在「代码深度分析结论」中填写：
```
### 平台归属确认
{卡片内容}
### 代码定位
⚠️ 该问题属于 {Android/游戏} 侧，代码不在本 monorepo，无法定位。

### 完整因果链

```

## 代码分支切换指令
{如果版本号不为空：}
**⚠️ 必须在分析前切换到版本对应的代码分支**，步骤如下：
1. 先尝试切换到 release 分支：`git checkout release/{version}`
2. 若 release 分支不存在，尝试 tag：`git checkout {version}`
3. 若两者均不存在，输出「⚠️ 未找到版本 {version} 对应的 tag/branch，将在当前主分支分析」后继续
4. 分析完成后，执行 `git checkout -`（或切回原分支），恢复代码库状态
{如果版本号为空：}
未提供版本号，**直接在当前主分支进行分析**，无需分支切换。

## 综合根因分析结论（已由 Bugly + 伽利略分析得出）
{将 Step 6 输出的「综合根因判断」部分完整粘贴至此}

3. **影响范围评估**：该问题是否影响其他路径或用户场景？
4. **修复建议**：给出具体的代码修复方向（不需要直接改代码，给出方向即可）

输出格式：
## 代码深度分析结论
### 实际分析分支
{所在分支/tag 名称，如「tag: 8.5.1」或「主分支（未提供版本号）」或「主分支（version 8.5.1 未找到对应 tag/branch）」}
### 代码定位
{文件路径、类名、方法名、行号}
### 根因验证
{确认或修正根因，说明代码层面原因}
### 影响范围
{是否影响其他路径或用户}
### 修复建议
{具体修复方向}

### 完整因果链
基于以上代码分析，用纯文本 ASCII 图输出从用户行为到指标影响的完整因果链。格式参考如下（根据实际情况灵活调整层级和分支，不强求完全对齐）：

```
用户行为（{一句话描述触发动作}）
  |
  ▼
{触发的技术路径描述}
{如有版本差异，分两支展示：}
  |—— {版本 A 或条件 A}（如：10.112.0415 及更早版本）—————|
  |    {代码行为 A}                                           |
  |    → {结果 A}                                            |
  |—— {版本 B 或条件 B}（如：10.112.0429 含 commit xxx）—— |
       {代码行为 B，新增/修改的逻辑}
       ├── 分支条件1（如：canOpenURL=YES）
       |    → {调用链步骤1}
       |    → {调用链步骤2}
       |    → {最终结果（含量化数据，如失败率）}
       └── 分支条件2（如：canOpenURL=NO）

            → {结果（无记录/正常/异常）}
  |
  ▼
监控指标影响（{指标名}）：
  {指标变化前}（{时间}）→ {指标变化后}（{时间}），{变化幅度}

```
**输出要求**：
- 因果链必须基于本次实际代码分析结果生成，不得照抄模板内容
- 若无版本差异，去掉版本分支层，直接展示单一代码路径
- 若无监控指标数据，此行可省略
- 链路中的数据（失败率、时间戳等）必须来自 Step 5/6 的真实分析数据
```
